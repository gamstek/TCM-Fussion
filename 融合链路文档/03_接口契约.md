# 03｜接口契约

同步版本 v7.0｜2026-11-17。用于连接真实 A、多图接口、规划器与 MCP。

## 1. 多图接口

```text
run_multi_view(source_dir, *, output_root=None, manifest=None,
               config_template=None, a_python=None, dry_run=False,
               case_name=None)
```

输入 manifest：

```json
{
  "views": [
    {"view": "a.jpg", "sha256": "<sha256>"},
    {"path": "sub/b.jpg", "sha256": "<sha256>"}
  ]
}
```

约束：

- `views` 至少 1 项；
- 路径在 source-dir 内；
- 路径、内容唯一；
- SHA256 必须匹配；
- 参考标签不写入配置。

输出：

```text
dry_run=true  → 准备 case 目录
dry_run=false → runs/<run_id>
```

`case_name` 只影响目录名；`sample_id` 另做 ASCII 清洗。`case_name` 不能为空，不能包含 `<>:"/\|?*` 或控制字符，不能是 `.`/`..`、Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1-9`、`LPT1-9`），不能以空格或点结尾，且不超过 100 字符；违规统一返回 `MULTI_VIEW_NAME`。

### Fast 路径字段

```json
{
  "fast_fallback_max_features": 2,
  "fast_fallback_max_locate_calls": 6,
  "fast_classify_max_per_view": 3,
  "context_compact": true,
  "context_recent_observations": 6,
  "context_recent_operations": 8,
  "context_max_actions": 20,
  "auto_measure_after_segment": true,
  "feature_scan_enabled": true,
  "candidate_group_verification": true,
  "suppress_repeated_measurement": true,
  "supporting_probe_total": 6,
  "supporting_probe_per_candidate": 2,
  "max_seconds": 2400,
  "tool_timeout_seconds": 180,
  "feature_scan_tile_policy": "full",
  "feature_scan_max_tiles": 4,
  "feature_scan_concurrency": 2
}
```

含义：

```text
fast（标准路径，无 false 开关）
  YOLO 先检，CNN batch 分类所有 YOLO crop；
  不默认创建 propose/screen/hybrid。
  `fast_yolo_stage2` 仅为历史配置兼容保留：schema 只接受 true，缺失时按 true 补齐。

fast_fallback_max_features
  样本的整组视野仍缺 required feature 时，每次最多补几个 feature。

fast_fallback_max_locate_calls
  一次 fallback hybrid 的总 locate 上限。

feature_scan_tile_policy
  full：4 tile 全并发，全空即弃；
  prescreen：先 pilot，空即停。

context_max_actions
  每轮模型最多看到多少个高价值动作；完整合法集合仍在内部 choices。

auto_measure_after_segment
  segment quality=valid 且 scale valid 时，同操作自动测量。

feature_scan_enabled
  默认 true。设为 false 时，菜单移除逐类补扫及旧配置的合并补扫。
  auto_prepare_stage、auto_required_measurement 只用于读取历史配置。
  feature_scan_tile_size、feature_scan_overlap 也仅作历史兼容，切块由原图尺寸和分块上限决定。

candidate_group_verification
  top required 已满足后，竞争候选 required 只做一次核验；每个候选最多一次，
  阴性/未知后不再扩散；candidate_group_incomplete 只在有合法动作时保留。

suppress_repeated_measurement
  同一 feature 对活动候选 required 已有有效量程内测量时，
  不再提供重复 segment/measure。

supporting_probe_total / supporting_probe_per_candidate
  supporting presence_check + feature_scan 的统一预算；
  共享 supporting feature 只提供一次。
```

## 3. A 契约

```text
predict_a / a_prediction.json
```

每图五折：

```text
view_predictions[].fold_rankings
```

每折包含：

```text
rank / label / probability
```

Agent 默认每折 Top-3。折数不一致、榜单非法或缺少逐折数据时拒绝该 A 结果。

## 4. B 工具契约

单图/ROI/crop 目标：

```text

locate_feature(locate:roi:...)
classify_crops_batch(crops:...) / classify_target(crop:...)
segment_instance(crop:...)

```

fast fallback：

```text
feature_scan:<image>（旧配置为 hybrid_scan）
features[]: missing required feature
max_locate_calls: fast_fallback_max_locate_calls
```

`feature_scan`：

```text
feature_scan:<image>:<feature_id>
max_tiles: 每个 feature 的 tile 上限
```

`locate_feature` 参数：

```text
roi / feature_id / locate_expand / locate_min_box_side / locate_min_roi_side
```

## 5. 动作与证据

规划器只能选当轮合法 `action_id`。运行时校验：

- 工具是否启用；
- 目标/参数是否匹配；
- 前置工件；
- 身份/标定/质量；
- 证据版本；
- 网络、观察、重算、资源预算。

`identity_pending` 是动作门：

```text
未分类 identity crop
→ 只允许 classify 最高分 crop
→ classify 尝试前不进入 segment/measure
```

无高分绕过；身份未确认不得进入测量。

## 6. scale 契约

```text
crop.px_per_um 可为空
```

- `detect_fov_initial` 自动标定失败时保留 YOLO 框，`px_per_um=None`；
- 后续 `calibrate_fov` 可补；
- 没有可信 `px_per_um` 时不得输出 μm；
- 不能因为自动标定失败丢弃检测框或伪造尺度。

## 7. 输出契约

```text
job.json
a_prediction.json
agent_trace.json
workflow/operations.json
workflow/action_timeline.json
workflow/ops/
feature_audit/feature_audit.json
image_audit/*/audit.json
agent_verdict.json
fusion.json
output.json
final_evidence.json
final_assessment.json
report.md
```

`output.json` 必须保留：

```text
status
top_candidate
candidates
strong_observations
classifications
review_required
provisional
```

`provisional` 只读当前有效 evidence snapshot 的 classification；历史 operation 中的失效分类不参与。

`provisional`：

```text
schema = provisional-ranking/v1
policy = temporary only; formal unchanged
ranking[]:
  candidate_id / display / provisional_score / formal_score
  provisional_delta
  formal_support_count
  criterion_states[]:
    feature_id / role / tier / state / weight
    provisional_contribution / formal_contribution
    instance_ids / formal_state / pending
  pending_verification[]
```

状态权重：

```text
VERIFIED_MATCH     1.0
DETECTED_PENDING   0.5
PARTIAL_MATCH      0.25
CONFLICT            0
NOT_DETECTED        unknown
UNKNOWN             unknown
```

0.5/0.25 不进入 `support_count`，不改变正式 verdict。

`top_candidate.selection` 可为 `formal` 或 `provisional`；`selection=provisional` 只表示 tentative 首选，正式 `formal_conclusion_id`/`support_count` 不变。

`fusion.json` 的 `fused_score` 是未校准排序分；正式结论仍由原规则授权。

维护说明｜v7.0｜2026-11-17：同步 stop_decision、auto_required_measurement、语义终止、2400 秒预算和身份门。

## 8. 当前停止契约

`assess` 生成：

```text
stop_decision:
  can_finish
  can_review
  recommended_exit
  blockers[]
```

语义：

```text
can_finish=true
  → 允许 finish

can_finish=false
  → finish 不是合法正式结论
  → 仍可继续合法动作

can_review=true
  → 始终允许 request_review

blocker.actionable
  → 是否存在合法动作能解决该 blocker
```

`request_review` 不因 `useful_coverage_incomplete` /
`candidate_group_incomplete` 被拒绝；  
它是证据不足的正常出口。

`finish` 被 veto 后不会在下一轮反复出现。

## 9. 当前 segment/classify 终止

```text
同一 crop / 同一源图 + 特征 + 高 IoU 区域
segment quality=review/failed
→ 不自动重发 segment
→ 只有新 crop 明显不同（IoU < 0.85）或 repair 决策才重开

同一 crop classify_target
→ 只自动尝试一次
→ 不可判/other 后不再自动重试
```

## presence 可选定位扩展（PRESENCE-001）

旧 `present/conf/reason/ok` 继续兼容。模型可在同一响应增加 `box`：

```json
{"present":true,"conf":0.9,"reason":"可见疑似结构",
 "box":{"bbox":[10,20,50,80],"coordinate_space":"model_input_pixels"}}
```

`ToolRegistry.PRESENCE_BOX_SCHEMA` 是该可选工具字段的唯一 schema；`StrictClient` 将有效/无效提示规范化为 `result.localization_proposal`，非法可选字段不抹去合法旧观察。原图 SHA、实际发送宽高、全图缩放逆变换由主机读取生成；不接受模型提交的映射。EXIF 方向未明确归一化时不推测坐标，继续保留旧观察。

`LocalToolbox` 返回并记账独立字段 `presence_localization`：policy_version、mode、source_image_sha256、feature_id、localization、quality、identity、findings、verification_basis、usage_eligibility；成功定位另含 source_tight_bbox、crop_bbox、transform、model_input_size、spatial_agreement、artifacts。`react_graph` 保留字段并送入后续规划上下文，最多汇总最近 8 条；不修改原规则证据摘要。

当前策略 `presence_localization_shadow_v1`，identity 为 pending、所有新增用途资格为 false。框通过不等于身份通过；旧 P1/C 规则仍可消费合法旧 presence，两套状态不能混为一个“验证通过”。目标紧框 `target.png`、扩框 `context.png`、诊断 `diagnostic.json` 保存于当前观察账本同级 `presence_localizations/<action_id>/`，不是交付 CropMeta，不能自动进入正式分割/测量或 high-score override。

状态投影：低置信/工具失败→unknown；有效未观察到→not_observed_local；阳性无框或非法框→present_unlocalized；合法框→present_pending。原始检测框也是模型假设，扩框不能当目标物理边界，重叠不能自动去重或确认身份。

变更记录｜PRESENCE-001｜2026-11-13｜新增兼容工具扩展与影子诊断；未校准身份阈值、未声称准确率提升。
