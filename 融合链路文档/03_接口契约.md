# 03｜接口契约

同步版本 v5.0｜2026-11-08。用于连接真实 A、多图接口、规划器与 MCP。

## 1. 多图接口

```text
run_multi_view(source_dir, *, output_root=None, manifest=None,
               config_template=None, a_python=None, dry_run=False,
               case_name=None)
```

输入 manifest：

```json
{
  "views": [
    {"view": "a.jpg", "sha256": "<sha256>"},
    {"path": "sub/b.jpg", "sha256": "<sha256>"}
  ]
}
```

约束：

- `views` 至少 1 项；
- 路径在 source-dir 内；
- 路径、内容唯一；
- SHA256 必须匹配；
- 参考标签不写入配置。

输出：

```text
dry_run=true  → 准备 case 目录
dry_run=false → runs/<run_id>
```

`case_name` 只影响目录名；`sample_id` 另做 ASCII 清洗。`case_name` 不能为空，不能包含 `<>:"/\|?*` 或控制字符，不能是 `.`/`..`、Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1-9`、`LPT1-9`），不能以空格或点结尾，且不超过 100 字符；违规统一返回 `MULTI_VIEW_NAME`。

## 2. 配置契约

```text
config/multi_view.json
```

当前关键字段：

```text
agent.mode=active
agent.planner=llm
agent.transport=mcp
agent.workflow.execution=active
agent.workflow.agent_policy=adaptive_v2
agent.workflow.detector=yolo
a.mode=cli
b.mode=run
allow_recorded=false
```

模板不允许：

- 旧 case 图像路径；
- A 缓存路径；
- 参考标签；
- 模拟 routing；
- `p0_priority`。

## 3. A 契约

```text
predict_a / a_prediction.json
```

每图五折：

```text
view_predictions[].fold_rankings
```

每折包含：

```text
rank / label / probability
```

Agent 默认每折 Top-3。折数不一致、榜单非法或缺少逐折数据时拒绝该 A 结果。

## 4. B 工具契约

单图/ROI/crop 目标：

```text
detect_fov_initial(image_id)
propose_regions(image_id)
roi_screen(image_id)
locate_feature(locate:roi:...)
classify_target(crop:...)
segment_instance(crop:...)
measure_instances(seg:...)
```

批量 screen：

```text
roi_screen_batch(screen:batch)
```

目标需带：

```text
items[]: image_id / source / regions / feature_id / parents
```

结果：

```text
screens[]: 每个视野的 screen.json
```

由 `WorkflowSession.accept` 一次提交多个 screen artifacts。

## 5. 动作与证据

规划器只能选当轮合法 `action_id`。运行时校验：

- 工具是否启用；
- 目标/参数是否匹配；
- 前置工件；
- 身份/标定/质量；
- 证据版本；
- 网络、观察、重算、资源预算。

`identity_pending` 是动作门：

```text
未分类 identity crop
→ 只允许 classify 最高分 crop
→ 清除 stop 建议
```

高分 `locate_override` 例外。

## 6. 输出契约

```text
job.json
a_prediction.json
agent_trace.json
workflow/operations.json
workflow/ops/
agent_verdict.json
fusion.json
output.json
final_evidence.json
final_assessment.json
report.md
```

`output.json` 必须保留：

```text
status
top_candidate
candidates
strong_observations
classifications
review_required
```

`fusion.json` 的 `fused_score` 是未校准排序分；正式结论仍由原规则授权。
