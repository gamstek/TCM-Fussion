# 01｜架构总览

同步版本 v5.0｜2026-11-08。运行者可用本页确认 A、B、C 的边界。

```text
原图（N 张）
→ A 每图五折推理 → 逐折 Top-K
→ WorkflowRuntime / EvidenceRuntime
→ YOLO 初检 → 本地 ROI → GLM screen/locate → GLM classify
→ 标定、分割、测量
→ 原规则 decide
→ A/B 融合与 final_assessment
```

## 1. 三层边界

| 层 | 输入 → 输出 | 说明 |
|---|---|---|
| A | 原图与权重 → 每图五折概率、逐折 Top-K | 药材种类；每折独立，不取平均榜替代逐折 |
| B | 原图/已有工件 → 检测框、crop、screen、identity、mask、尺寸 | 只有真实工具和合格工件才成为证据 |
| C | A/B 证据、预算、工具能力 → 规划动作、停止、复核 | LangGraph ReAct + MCP/本地工具，不替模型编造动作 |

## 3. 当前关键设计

### A 与 YOLO

- A 给药材类别；YOLO 给显微特征类别和框。
- YOLO 初检逐图执行，当前默认 CPU；`detect_fov_initial` 不是药材分类。
- `classify_target` 以 GLM 为主；required crop 可再跑 YOLO crop 复核，YOLO 未命中时保留 GLM 结论。

### screen 与 locate

- `roi_screen`：每视野 6 个 ROI 的 contact sheet，GLM 排名，不返回框。
- `roi_screen_batch`：多个视野缺失 screen 时按 `screen_concurrency` 并发执行 worker，结果由 Session 一次提交。
- `locate_feature`：在 screen top-k ROI 中做 GLM 定向定位；同一 `(image, ROI)` 已有 locate 后不重复。
- `locate_expand=1.5`：定位框先扩再裁 crop。

### 身份完整性门

存在 `identity_required` 且未分类的低分 locate crop 时：

```text
identity_pending
→ 必须先 classify 最高 det_score crop
→ 再允许继续 locate / 暂停 / review
```

`det_score >= 0.8` 可走 `locate_override`，不强制 classify；低于 0.8 不享受绕过。

### 预算与数量

```text
max_initializations = N + initialization_reserve
max_locate_attempts = max(4, locate_attempts_per_view * N + locate_attempt_reserve)
```

图片数量不固定；`max_planning=32`、`max_observations=10`、`max_api_calls=60`、`max_resource_units=220` 仍是固定安全上限。
