# 01｜架构总览

同步版本 v7.5｜2026-11-17。运行者可用本页确认 A、B、C 的边界和当前 fast 路径。

当前自主路径的调查顺序与停止边界以 [13 调查建议与硬约束分离](13_调查建议与硬约束分离.md) 为准；本页数据依赖不代表强制调查顺序。
```text
原图（N 张）
→ A 每图五折推理 → 逐折 Top-K
→ WorkflowRuntime / EvidenceRuntime
→ fast 路径：YOLO 初检
→ 自动 CNN stage2 batch 分类
→ top required 已验证 crop 可自动 segment + measure
→ 自动 mandatory scene_check
→ required / 竞争候选检查
   ├─ 共享账本命中：复用已有观察
   ├─ 仍有合法缺口：模型选择动作
   └─ 缺失 required：有限 GLM feature_scan / presence
→ 原规则 decide
→ A/B 融合与 final_assessment
```

## 1. 三层边界

| 层 | 输入 → 输出 | 说明 |
|---|---|---|
| A | 原图与权重 → 每图五折概率、逐折 Top-K | 药材种类；每折独立，不取平均榜替代逐折 |
| B | 原图/已有工件 → 检测框、crop、screen、identity、mask、尺寸 | 只有真实工具和合格工件才成为证据 |
| C | A/B 证据、预算、工具能力 → 规划动作、停止、复核 | LangGraph ReAct + MCP/本地工具，不替模型编造动作 |

## 3. 当前关键设计

### A

- A 只给药材候选；不提供显微特征框。
- 每图五折分别给 Top-K，默认每折 3 个；候选兴趣由此映射去重。
- A 不因为 B 的候选池为空或已有结论而被改写。

### Fast 路径（当前默认）

```text
fast_yolo_stage2 = true
```

```text
每图 YOLO detect
→ 所有 YOLO crop 全部保留
→ CNN stage2 对全部 crop 做一次 batch 分类
→ top required 已验证 crop：自动 segment + auto measure
→ mandatory scene_check
→ 合并同一样本各视野，检查 required feature
   ├─ 有：允许标定/测量/候选核验
   └─ 无：有限 GLM feature_scan / presence 兜底
```

关键约束：

- YOLO 框全部保留；GLM 不覆盖 YOLO 框。
- CNN 高置信直接写 `source=cnn`；低置信/other 回退 GLM classify。
- 标准路径不创建 `propose_regions` / `roi_screen` / 普通 `hybrid_scan` 目标；前两者已移除。
- 只有整组视野仍缺某个 **A 候选 required feature** 时，才为可补查的视野创建 fallback，每图最多一次。
- fallback 上限：

```text
fast_fallback_max_features = 2
fast_fallback_max_locate_calls = 6
feature_scan_tile_policy = full
```

```text
3 个 missing feature 最多各自 4 tiles
→ 每图最多 12 次 locate
→ 4 tiles 并发；任一有 crop 就合并
→ 全空立即返回，不重试
```

### YOLO / GLM / stage2 的职责

| 模块 | 作用 | 边界 |
|---|---|---|
| YOLO | 14 类显微特征框 | 召回较低；不判药材 |
| GLM locate | 指定 feature 在 ROI/tile 找框 | 会漂移；必须允许空框 |
| CNN stage2 | 对已有 crop 做 14 类分类 | 不生成框；低置信回退 GLM |
| GLM classify | crop 身份兜底 | 不重新定位；required crop 可做 YOLO crop 复核 |

### required coverage

`coverage` 同时维护：

```text
useful / missing_useful          # 任意 feature 覆盖
required_features                # A 候选 required feature
required_all / missing_required  # required 覆盖
```

`output.json` 另有 `provisional`：

```text
classification → VERIFIED_MATCH 1.0 / DETECTED_PENDING 0.5
                / PARTIAL_MATCH 0.25 / CONFLICT 0
```

它只影响暂定排序，不改变正式 verdict/support_count；`required_states` 给 Agent 用于补查。

fast 模式下：

- `stop_decision` 区分 finish/review；`request_review` 不被 coverage veto 拒绝；
- 只有缺 required feature 才触发有限 GLM fallback；
- 不再把“检出纤维”当成“针晶已覆盖”；
- 同一 crop/高 IoU 区域 segment review 后不自动换 ROI 重试，classify_target 每 crop 只自动一次。

### locate 质量

```text
locate_min_roi_side = 256
locate_min_box_side = 90
locate_expand = 1.5
```

- 观察 ROI 小于 256 时围绕中心扩展；
- tight box 小于 90 时扩展，保留 `source_tight_bbox`；
- 无目标必须返回 `{"objects":[]}`，不伪造 crop；
- 任何 `identity_required` crop 未通过 classify/身份确认时不得 segment/measure；
- 高分 `det_score` 只影响定位优先级，不绕过身份门；
- blank阻断分割；low_detail保留提示，同类别身份确认后可选择分割，不授予尺寸资格；
- 同特征 GLM 与 YOLO IoU >= 0.5 时保留 YOLO。

### 标定与检测解耦

`detect_fov_initial` 产出 YOLO 框后，自动标定失败只置：

```text
px_per_um = None
```

不再让 YOLO 检测整体失败；后续可显式 `calibrate_fov`。

### ReAct

`adaptive_v2 + llm + mcp + active` 下，planner 从合法动作中选择；运行时负责：

```text
证据版本
工具前置条件
身份/质量/标定
预算/时间
stop_decision（can_finish/can_review/blockers）
finish 与 request_review 的权限区分
```

`stop_decision.recommended_exit`：

```text
finish   → 正式证据允许收尾
continue → 还有可执行 blocker
review   → 没有可执行路径，交人工复核
```

Agent 不直接画框、不直接分类、不绕过证据门。

## 4. 路径唯一性

`fast` 是唯一标准路径，`fast_yolo_stage2` 只作历史配置兼容且只接受 `true`；不存在旧的 `propose_regions` / `roi_screen` / `needle_scan` 链路，相关工具已从注册表和运行时移除。

## 5. 当前未实现 / 边界

- `classify_crops_batch` 提供逐实例批量 CNN；`classify_target` 保留单 crop 路径；两者共享 CNN 缓存。
- YOLO 逐图、默认 CPU；无 batch/GPU 自动切换。
- `locate_feature` 仍逐 ROI；没有 locate 全局并发。
- fast fallback 是“required feature 缺失时补扫”，不是零漏检保证。
- `full` 4 tile 全空即弃；`prescreen` 更省调用但更易漏。
- 同一 crop/同一源图+特征+高 IoU 区域 segment review 后不自动换 ROI 无限重试。
- classify_target 每 crop 只自动尝试一次；不可判后不再自动重试。
- 网络/上游失败按 service failure 记录，不伪造 B 证据。
- `max_seconds=2400` 是 Agent 工作流预算；final_assessment 可略超总墙钟。
