# 01｜架构总览

同步版本 v6.0｜2026-11-10。运行者可用本页确认 A、B、C 的边界和当前 fast 路径。

```text
原图（N 张）
→ A 每图五折推理 → 逐折 Top-K
→ WorkflowRuntime / EvidenceRuntime
→ fast 路径：YOLO 初检 → CNN stage2 批量分类
→ required feature 覆盖检查
├─ 覆盖：标定、分割、测量
└─ 缺失：一次 GLM hybrid 兜底（required feature × 4 tiles，受 locate cap）
→ 原规则 decide
→ A/B 融合与 final_assessment
```

## 1. 三层边界

| 层 | 输入 → 输出 | 说明 |
|---|---|---|
| A | 原图与权重 → 每图五折概率、逐折 Top-K | 药材种类；每折独立，不取平均榜替代逐折 |
| B | 原图/已有工件 → 检测框、crop、screen、identity、mask、尺寸 | 只有真实工具和合格工件才成为证据 |
| C | A/B 证据、预算、工具能力 → 规划动作、停止、复核 | LangGraph ReAct + MCP/本地工具，不替模型编造动作 |

## 2. 主要部件

| 部件 | 职责 |
|---|---|
| `lib/multi_view.py` | 任意 N 张图的准备、哈希校验、新 case、空 A 缓存 |
| `lib/pipeline.py` | A → workflow → 融合 → 交付层 |
| `lib/adapters.py` | 原始 A CLI 输出接入每图五折 |

| `lib/evidence_runtime.py` | 规则摘要、候选兴趣、观察与判据 |

## 3. 当前关键设计

### A

- A 只给药材候选；不提供显微特征框。
- 每图五折分别给 Top-K，默认每折 3 个；候选兴趣由此映射去重。
- A 不因为 B 的候选池为空或已有结论而被改写。

### Fast 路径（当前默认）

```text
fast_yolo_stage2 = true
```

```text
每图 YOLO detect
→ 所有 YOLO crop 全部保留
→ CNN stage2 对全部 crop 做一次 batch 分类
→ 合并同一样本各视野，检查 required feature
   ├─ 有：允许标定/分割/测量
   └─ 无：一次 GLM hybrid 兜底
```

关键约束：

- YOLO 框全部保留；GLM 不覆盖 YOLO 框。
- CNN 高置信直接写 `source=cnn`；低置信/other 回退 GLM classify。
- fast 模式默认不创建 `propose_regions` / `roi_screen` / 普通 `hybrid_scan` 目标。
- 只有整组视野仍缺某个 **A 候选 required feature** 时，才为可补查的视野创建 fallback，每图最多一次。
- fallback 上限：

```text
fast_fallback_max_features = 3
fast_fallback_max_locate_calls = 12
feature_scan_tile_policy = full
```

```text
3 个 missing feature 最多各自 4 tiles
→ 每图最多 12 次 locate
→ 4 tiles 并发；任一有 crop 就合并
→ 全空立即返回，不重试
```

### YOLO / GLM / stage2 的职责

| 模块 | 作用 | 边界 |
|---|---|---|
| YOLO | 14 类显微特征框 | 召回较低；不判药材 |
| GLM locate | 指定 feature 在 ROI/tile 找框 | 会漂移；必须允许空框 |
| CNN stage2 | 对已有 crop 做 14 类分类 | 不生成框；低置信回退 GLM |
| GLM classify | crop 身份兜底 | 不重新定位；required crop 可做 YOLO crop 复核 |

### required coverage

`coverage` 同时维护：

```text
useful / missing_useful          # 任意 feature 覆盖
required_features                # A 候选 required feature
required_all / missing_required  # required 覆盖
```

fast 模式下：

- `finish_veto` 用 `missing_required`；
- 只有缺 required feature 才触发 GLM fallback；
- 不再把“检出纤维”当成“针晶已覆盖”。

### locate 质量

```text
locate_min_roi_side = 256
locate_min_box_side = 90
locate_expand = 1.5
```

- 观察 ROI 小于 256 时围绕中心扩展；
- tight box 小于 90 时扩展，保留 `source_tight_bbox`；
- 无目标必须返回 `{"objects":[]}`，不伪造 crop；
- `det_score >= 0.8` 的高分 crop 即使 `box_quality=blank` 也保留后续路线；
- 低分 blank 阻断 segment；low_detail 只标记 review；
- 同特征 GLM 与 YOLO IoU >= 0.5 时保留 YOLO。

### 标定与检测解耦

`detect_fov_initial` 产出 YOLO 框后，自动标定失败只置：

```text
px_per_um = None
```

不再让 YOLO 检测整体失败；后续可显式 `calibrate_fov`。

### ReAct

`adaptive_v2 + llm + mcp + active` 下，planner 从合法动作中选择；运行时只负责：

```text
证据版本
工具前置条件
身份/质量/标定
预算/时间
finish_veto
```

Agent 不直接画框、不直接分类、不绕过证据门。

## 4. 兼容的非 fast 路径

`fast_yolo_stage2=false` 时保留旧链路：

```text
detect_fov_initial
→ propose_regions
→ roi_screen / roi_screen_batch
→ locate_feature
→ classify_target
→ segment / measure
```

`screen_max_rois=4` 只截断 GLM 输出 ROI，不减少送进 screen 的 192 个候选区域。

## 5. 当前未实现 / 边界

- `classify_batch` 未实现；`classify_target` 仍是单 crop 动作，但首次 CNN 会 batch。
- YOLO 逐图、默认 CPU；无 batch/GPU 自动切换。
- `locate_feature` 仍逐 ROI；没有 locate 全局并发。
- fast fallback 是“required feature 缺失时补扫”，不是零漏检保证。
- `full` 4 tile 全空即弃；`prescreen` 更省调用但更易漏。
- 网络/上游失败按 service failure 记录，不伪造 B 证据。
