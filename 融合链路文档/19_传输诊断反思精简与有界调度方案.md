# 19｜传输诊断、反思精简与有界调度方案

版本v0.1｜2026-11-18｜分析及待实施方案；不代表新增代码已上线。

## 1. 目的与读者

供融合编排、工具及测试开发者阅读。目标是在保留主解释和竞争解释的合法取证机会下，减少重复上下文与串行等待。沿用LangGraph/MCP、ToolSpec、预算器和原证据资格，不增加思考Agent，不写死调查顺序。真实依据是白芍单图case_fair_investigation_single_20261118_093651，425.578秒、11规划、6原图观察。

## 2. 范围与已确认事实

真菌团块调用总时延62.328秒，其中HTTP60.719秒、worker60.984秒。错误RemoteDisconnected，send_to_headers_seconds及HTTP状态未记录，attempts=1、usage=null、accepted=false。可定位到HTTP返回响应头之前连接被对端关闭，worker正常生成结构化失败，MCP并非一直无输出。不能确认请求是否被模型处理或计费。

观察预算150秒，当前HTTP配置180秒；证据不是本地截止先触发。约60秒可能是网关/代理首响应或空闲上限，也可能是上游负载或网络瞬态，均待验证。当前环境存在HTTP/HTTPS代理设置，但当次是否经过代理、哪一跳关闭没有记录，不能直接归咎服务商或代理。

本篇不修改超时、网络、判据或模型配置，不进行额外付费请求。

## 3. 当前Reflection部件与职责

ReflectionController.record冻结问题语义键、输入指纹及实际收益；propose在无收益、重复失败或候选状态停滞时由程序整理反思卡。卡包含失败类别、事实引用、可避让键、允许的改变条件及退出建议。

react_graph把卡放入下一次正常规划的task_reflection。模型可同时返回主选择和reflection_patch，也可不提交补丁。apply校验当前卡绑定、schema、已知候选及避让范围；补丁可激活合法假设、回避精确失败动作、提出退出建议，不能改图像、证据、量纲、判据或预算。随后record检验是否真换输入/问题、是否有新信息。它是任务内策略记忆，不是权重训练；同一请求完成规划与策略修订仍消耗更多输入/输出token。

本次8卡、3补丁应用、1拒绝，3份policy_delta均无当前菜单/范围变化；第一份后验有局部新观察，第二份无进展，第三份随review退出。不能称因果改进或跨任务自进化。

## 4. 数据与控制流

```text
实际工具结果 → 本地事实/收益及服务诊断
→ 未解决问题卡去重 → 正常ReAct请求（当前状态＋新变化＋可选补丁）
→ 模型选语义目标/当前问题 → 主机验证依赖、权限、预算
→ 已授权独立节点执行 → 单一提交者验证来源和依赖后合并
→ 普通中间结果交给下游；关键冲突/失败/目标完成才回ReAct
→ 原规则及确认资格 → 一致结构化交付
```

新DAG继续遵守文档09：模型不预生成未来crop ID或具体工具串。发现新实例后由ReAct选择对象；对已选定实例，程序按真实依赖晚绑定。不能把任意一份阳性当作全局目标满足并取消竞争调查。

## 5. 具体修改包及落点（均待实施）

S0传输：在现有adjudicator HTTP钩子和hard_calls/agent_tools中增加client_request_id、阶段时间、目标路由/代理标识（脱敏）、响应request_id（收到时）、状态和结果大小。连接/上传/服务端等待目前混在一起，不能从总时延猜模型推理时间。复查必须用新任务单工具、同图同配置少量对照原路径/可用直连；直连须符合实际网络条件。不自动重发未知计费的视觉请求，不只把超时调大。

S1上下文：planning_context/compact_evidence将共享物理事实只发一份，以引用连接各候选判据；问题卡共享权限/后续条件说明，动作参数只在菜单保存一份。每轮保留完整候选状态、主解释缺口、重要竞争支持/反证、资格、当前任务及预算。静态KB详情按需读，不能把仍有关的候选删掉。无服务端会话状态时不能只发delta并假定模型记得上一轮；应发送紧凑完整状态＋变化摘要。供应商缓存需实测，当前cached_tokens均0。

S2反思：reflection_controller对未解决问题维护稳定ID，不再以记录数增长反复生成相同卡；服务故障与图像身份/分割问题分开。只发当前问题、上次策略变化及后验，完整历史落盘。新增避让/激活与单纯退出建议分别计量；同一no-op补丁不反复携带长事实。改变条件未落实、新信息为零时不能记自进化。补丁拒绝仍保留合法主动作，不加独立付费纠正轮。

S3调度：扩展react_graph/WorkflowSession，允许模型授权少量当前独立问题/已绑定实例目标；沿用现有共享预算预约、每worker独立产物和单一提交者。目前Q组只支持presence/scene、语义目标不能与观察伙伴并行，不能仅改max_parallel就声称解决。新增节点需记录goal_ref、read_set、write_set、预算预约、状态（拟新增内部字段）；同实例竞争修复串行。输入依赖不变的独立分支可合并，不能仅因全局head改变就互相作废。

S4尾部与收尾：替换等齐gather的屏障式交接，允许成功的独立分支先提交并推进已授权下游；pending状态显式进入规划，防重复请求。重大冲突或阻塞可触发一次必要重规划，普通节点成功不额外问模型。超时/取消后拒绝迟到证据；远端是否停止/计费单列。收尾先比较模型是否改变候选，只有纯文案分支才可用模板替代；直接关闭final_assessment_llm可能改变暂定结果，必须先对拍。

## 6. 失败与降级

连接断开、超时和无效输出始终unknown，不是不存在。预算预约不重复扣、不虚假退还可能已计费请求；本地取消不等于服务端取消。read_set包含原图/crop/标定/工具及模型版本等实际依赖；结束epoch拒绝迟到提交。部分成功不能抹掉失败伙伴。当前decision_readiness_shadow不能作为取消其他调查或生产确认依据。

每个优化可独立关闭回退旧执行器，保留原工件和逐请求日志；不能靠放松mask QA、缩小候选组或混入真值来降低耗时。

## 7. 验收

先离线再新case真实验证。上下文去重须逐字段/引用对拍候选、资格、合法动作、关键观察和预算；反思去重要证明新问题不漏、旧问题不反复；调度验证并行重叠、依赖正确、预算上限、部分失败、迟到隔离及无同问题重复计费。不能把as_completed替换本身当成安全并行。

用A首选正确、A首选错误但其他折含真类、多视野和服务异常样本，按标本来源分组，参考答案只事后使用。先比较审查覆盖、正确/错误确认、复核和实际支持，再比较规划输入/缓存/次数、视觉请求、P50/P95墙钟与故障等待。数值目标由基线分布决定，本篇不编造生产时限。
