# 18｜主解释与竞争解释公平取证（FAIR-INVESTIGATION-001）

## 1. 目的与读者

供融合链路开发、测试和使用者阅读。本批修复白芍单图case_candidate_audit_single_20261118_090132暴露的主解释未核验、格式错误立即终止及交付候选不一致。目标是让模型公平比较取证价值，同时保留竞争候选挑战机会。不能把“全候选有记录”当作“全候选已执行”，不能用少规划证明识别改进。

## 2. 范围与证据

当时4折首选白芍，另一折首选未映射的玄明粉；Agent两轮先查郁金/茯苓及纤维，第3轮结构错误，YOLO未运行。模型看到A1初检，但旧账本把簇晶记为no_current_legal_action。根因是只关联直接特征动作，遗漏原图发现入口；初始G目标需现存crop，具体Q问题与通用初检表达不对等。模型内部原因仍不能由摘要断言。

本批只改融合编排、只读投影、反馈和回归；原A五折、YOLO/IGM权重、知识库、原B判据、身份/质量/标定/量纲、预算和图像库不改。没有固定Top1调查顺序，没有新思考Agent，没有用参考标签指导规划。

## 3. 组成部件

- planning_choices.decode：只归一decision里的已知字符串说明字段decision_summary/override_reason/reason/rationale/explanation；未知或混合执行字段仍拒绝。日志只保留安全字段名，不存无效自由值。
- autonomous_think：无法安全解码的PLANNER_CHOICE_INVALID，在原两次尝试上限内最多纠正一次；失败与纠正都扣真实planning/network/total、保留usage，第一次无工具执行。与原断连重试共享上限，不无限重问或猜首项。
- comparison_problems.evidence_paths：当前特征步骤与discovery_prerequisite共用真实action_id。初检只表示可能发现实例，不代表存在、支持或后继自动执行。
- prior_summary/investigation_focus：保留逐视野逐折首选计数、未映射首选、主解释required缺口及竞争支持。折间相关，计数不是独立投票或正确率；显示窗口保留主解释，不排除其他候选。
- output_projection：遵循已经引用校验的final_assessment交付候选；原融合榜保存在fusion_ranking。未知研判候选失效为undetermined，不拼接另一候选的判断。

## 4. 数据与控制流

```text
逐图逐折Top-K → 保留所有候选及未映射
→ 原规则资格事实＋当前动作 → 统一鉴别问题卡
→ 特征现状/共享消费者/当前入口/后续条件/成本与限制
→ ReAct自主选A动作、G实例目标、Q观察组或review
→ 工具受信校验及执行 → 分轴反馈 → 更新主解释缺口与竞争支持
→ 原规则＋保守交付授权 → 唯一研判候选 → output/report
```

没有crop时，簇晶问题可关联YOLO初检；选择初检只执行初检，后续根据真实工件重新规划。白芍和G1可以共用发现入口，但不同形态/量纲的判据仍分开解释，不能为减少次数而强行合并。当前只实现可执行入口关联，未实现任意深度的多跳DAG或并行调度器。

## 5. 接口与配置

真实接口沿用decode(reply, context)、project_output(sample_id, verdict, result, a)；新增evidence_paths(runtime, actions, feature_ids)、prior_summary(interest)、investigation_focus(runtime, scored, audit)、readiness_shadow(audit, formal)。action_feedback.snapshot(scored, *, primary_ids=())新增可选先验主解释ID。

规划evidence.workflow中有investigation_focus和comparison_problems；每张问题卡保留current_states、required_by/supporting_by、entry_paths、future_requirements、costs、evidence_limits。本轮可见入口映射为实际A/O短号；菜单外入口不伪装可执行。planner_offer保存实际问题卡和主解释状态，便于验证模型到底看到了什么。详情仍由原read_evidence_detail读取，不新增付费审查。

无新增策略权重或阈值。原semantic_execution默认false；开启时仍只对现存实例目标晚绑定，不把问题卡冒充自动执行整条B。

## 6. 失败、反思与交付边界

candidate_support_changes、qualified_counter_changes、primary_required_progress、discrimination_progress分别记录。竞争支持增加、排序变化、局部未见不自动证明候选已区分；真实合格量纲反证单列。Reflection记录这些字段，只影响调查策略，不改变证据或裁决。

审计完整性与判定充分性已分开计算：decision_readiness_shadow不因supporting缺口单独判否，但保留所选required、竞争required、未映射及原规则授权。它仅为shadow，production_authorization_changed=false。未经独立风险/覆盖验证，原CANDIDATE_AUDIT_INCOMPLETE生产保护继续保留；不能把影子would_be_ready用作放行依据。本批没有宣称新的充分性策略已经发布。

review始终允许；存在其他可查对象不是强制付费打卡的理由。格式纠正不是停止后的反复重问，最多一次且真实计费。确认不足仍报告倾向和缺口，运行中断原因与交付复核原因分别记录。

## 7. 验收与演示

沿用项目根命令：`.venv\Scripts\python.exe -X utf8 -m TCM_Fusion.cli.main selftest`。最终540项（539通过、1历史参考缺失跳过）及原B59/21/125断言通过；原selftest整命令254.672秒。新增19项，80项专项通过。新增回归验证：无crop也有真实发现入口；合法说明字段不丢动作；未知字段不执行；纠正有界/收费/同菜单；主解释未核验不被竞争阳性抹掉；模型可先查竞争候选再回初检，也可直接初检；共同发现不合并不同判据；输出候选一致；影子资格不能提升确认；支持不伪装反证。

离线视觉与HTTP为明确fixture。初次失败、修复、源码哈希及最终统计位于项目根results/ui_out/fusion/verification/FAIR_INVESTIGATION_20261118/；以verification.json为最终口径。新真实测试必须新case、空A缓存、中性文件名；不能续跑上次快照冒充验证。比对先看主解释/竞争解释覆盖、错误确认、正确确认、复核，再看token、规划、时延。

新真实单图case_fair_investigation_single_20261118_093651已完成：425.578秒、11规划/6原图观察/14显式步，模型自主先初检，再做两个簇晶crop身份/分割，第二mask合格测量17.274558μm；随后调查郁金/茯苓、补扫G3方晶和淀粉粒，最后主动review。output/研判/报告均暂定白芍、需复核；一次服务断连保留unknown，0规划解析错误。3补丁应用但均无当前菜单/范围变化，不称自进化。

单轮开销并未自动下降：两次真实首请求66773→75336 UTF-8 JSON字节、prompt_tokens19134→21594；这是描述性对比，不是同覆盖节费实验。新信息有成本，后续应在维持相同语义及候选覆盖下去重，而不是隐藏主解释或竞争候选。
