# 05｜决策协议

同步版本 v4.3｜2026-11-06。主测试配置为 `adaptive_v2 + llm + mcp + active`。

## ReAct

- **Assess**：规则重评分，按证据、前置条件和尝试记录生成合法动作；提供停止建议 `stop_advisory` 与确认否决 `finish_veto`。
- **Think**：GLM 看五份逐折 Top-K、可映射候选判据、最近观察与预算。逐折默认前三。B 补查还可参考有正支持的前 3 个规则候选。模型从当轮可负担的合法动作中选择短编号，也可选择结束或复核。轨迹仅存动作理由摘要。
- **Act**：调用 MCP 或本地工具，验证观察或工件、记录失败及收益，再回到 Assess。规划、观察、重算和初始化分别计账，并受总网络、资源和时间上限约束。

模型可覆盖软建议并提交理由，程序可否决不满足硬约束的确认。同一调查方向连续两次逆停止建议继续，或步数、时间和合法动作边界触发时收尾；真实调查范围变化可重置旧路线的连续覆盖计数，不重置总预算，也不算证据收益。无效动作有界重提，仍失败则运行时复核。逐折模式的 Agent 停止判断以 B 证据为准。

## Reflection

- **任务内**：达到连续无收益阈值（默认 2）或 adaptive_v2 的动作执行失败时，程序生成 `task-reflection/v1` 卡，adaptive_v2 在新失败或持续无收益时刷新。从反馈提取失败事实和应避免的重复问题，供下一轮调度；无额外反思模型调用。若之后已经停止，卡不会产生后续动作。
- **离线规则经验**：`reflect → reflection-validate → reflection-publish` 是显式候选与回放实验，首版仅验证无收益阈值收紧的模拟记忆。
- **离线 LangMem**：`prompt-optimize → prompt-validate → prompt-publish` 处理训练轨迹和反馈，开发集回放验证后显式指定 `agent.prompt_release`。参考真值留在离线评估，线上不会自动发布或微调权重。发布验证绑定技能文件哈希，本次技能文字更新前发布的版本需要重新验证。

详见 [ReAct 源码](../lib/react_graph.py)、[反思卡](../lib/action_feedback.py)和[离线提示优化](../lib/prompt_optimization.py)。

## 2026-11-05｜上下文调查改进

模型回复可以附加 `investigate_candidates`（每轮最多3个知识库ID）与 `investigation_reason`。任务总计最多6个额外候选，写入 `workflow/investigation.json` 并由 MCP 读取。这里只扩大调查兴趣，不增加显微证据、不改变 A 的五折 Top-K，也不授予新工具权限。最终候选外采信仍需要 `open_strict` 的合法证据；不能把参考标签作为扩展依据。

MCP 服务接收请求前在主线程预加载已有数值/图像依赖，避免工作线程冷导入阻塞。有效阴性按视野回写，失败仍是 unknown。任务反思提供失败事实与质疑假设的问题，不强制下一工具；自进化效果仍需独立评测。

交付可始终生成报告，同时必须如实保留 `review_required`。`confidence` 保留 B 规则分，`fused_score` 是未校准排序分；重排不能继承另一候选的确认结论。D8 默认2类，单类放宽实验须显式配置 `agent.workflow.min_support_features=1`。决策审查共享规划/网络预算，任务关闭后不得再发请求。


## 2026-11-06｜假设生命周期与自主调查（CODE-062）

adaptive_v2 将 P0 判据缺口作为建议，不再按候选是否含 P0 自动升级为执行任务。模型读取全部合法动作、判据、观察、失败反馈、任务反思和当前假设状态，再决定下一步。强制场景、身份/标定/质量资格、权限和预算仍由程序校验；这些约束不指定应调查哪味药材。

模型回复可使用下列控制字段（每轮最多3项）：

```json
{
  "action_id": "本轮合法动作编号",
  "decision_summary": "本轮动作理由",
  "hypothesis_updates": [
    {"candidate_id": "知识库中已有的候选ID", "status": "paused", "reason": "根据已有工具反馈暂停该调查"}
  ]
}
```

状态为 proposed（提出）、investigating（调查中）、paused（暂停）、withdrawn（撤销本次调查）。暂停/撤销不证明候选不存在、不删除观察、不改变规则裁决；可因新信息重新进入 investigating。撤销的专属补救分支不再提议，共用特征仍可用于其他活跃假设。

状态更新通常在本轮工具动作结束、下一轮规划前生效；选择停止时立即提交。investigation.json 保存状态、理由、历史和原始决策依据的 evidence_digest；轨迹另外记录应用时的证据摘要。状态变化可清除旧路线的连续覆盖计数，但不算证据收益、不重置总预算和步数。

兼容旧 investigate_candidates/investigation_reason 提名字段；两个格式不能同时使用。提名只表示调查兴趣。场景自由描述中的“簇晶状”等措辞只能提出待核验线索，不能直接授予目标身份或强制优先级。全部提名与状态只接受已知知识库ID，额外候选总计最多6个。

检验是否真正自主：查看 planner_contexts 的输入与原始模型回复，及 agent_trace.json 的 hypothesis_update_requested/hypotheses_updated。程序不能替模型填写撤销理由或预设“先查簇晶再查针晶”。模拟来源必须标注 injected_planner，真实来源为 model。


CODE-062 新鲜度约定：`read_results` 保留历史查询并标注 `stale`。工作流只读动作的版本键覆盖实际工件版本、操作状态、假设状态和观察；标定变化即使不改变规则卡池，也会允许重新执行 read_scale。每轮 `evidence.workflow.calibration` 直接给出当前受信标定。特征卡的 UNCAL 可以表示尚无可信尺寸，不应被解释为“原图当前没有标定”。


## 2026-11-06｜停止调查后仍综合研判（CODE-063）

`override_exhausted` 表示连续两次覆盖停止建议且没有取得可重置计数的进展，运行时停止继续调查；它不是“没有结果”的诊断状态。正常返回的调查停止（上限、预算、截止、模型复核等）均进入独立收尾阶段。

收尾固定当前证据版本，读取五折各自Top-K、全部观察（含失败/阴性/unknown）、规则卡、测量、标定、QA、分类、操作记录和调查假设。`final_evidence.json` 保存完整账本和事实ID；`final_assessment.json` 给出当前倾向、支持、反证、缺口、候选比较和置信依据。输出及report.md展示综合判断。正式确认仍由原规则授权；A先验、不可判crop和假设状态不能替代显微证据。

真实联网运行默认 `agent.workflow.final_assessment_llm=true`，预留finalization池1次与对应network额度、2个总资源单元；使用同一总时间预算，默认 `final_assessment_seconds=30`。接近截止时可提前停止调查为收尾留时间，长工具已耗尽硬截止时只做本地汇总。可设false停用末次文本调用，但程序化综合判断仍生成。

末次文本调用不发图、不调用MCP、不新增证据。候选必须在知识库中，支持和反证必须引用账本中与该候选匹配的事实；服务失败、非法引用或证据包超限则回退程序化研判，并记录实际method、model_failure与usage。不因为停止码本身把合格结论降级，也不把不充分证据强行写成confirmed。

注意：融合排序top_candidate与综合研判candidate_id可能不同，报告同时保留来源；有分歧时保留复核。反证局限于完成观察的视野，未观察/超时/不可判仍是unknown。事实引用校验不等于模型解释的语义已通过独立临床或药材验收。
