# 05｜决策协议

D3-001：ReAct仍负责调查与停止。默认单步；实验语义目标只在显式开启且模型授权时执行，按当前工件逐节点绑定，关键阻塞立即回交。Reflection补丁在下一次正常规划中提出、严格校验、执行后回查，不增加独立模型调用。详情见[14](14_D3交付与验收.md)。

同步版本 v7.4｜2026-11-17。当前调查/停止边界见[13](13_调查建议与硬约束分离.md)。主测试配置为 `adaptive_v2 + llm + mcp + active`，默认走 fast 路径。

## 1. ReAct 循环

| 阶段 | 行为 |
|---|---|
| Assess | 规则重评分，读取证据、目标、预算、required coverage、假设，生成合法动作及停止建议 |
| Think | GLM 看逐折候选、判据、最近观察、预算和 coverage，选择当轮短编号或停止 |
| Act | 调 MCP/本地工具，校验结果，提交证据或记录失败，再回到 Assess |

规划器不能直接写证据；A 先验、判据缺口和假设状态都不是显微证据。

## 2. fast 路径的决策边界

默认：

```text
fast_yolo_stage2 = true
```

第一轮 Agent 应优先：

```text
detect_fov_initial（每图）
→ classify_crops_batch（YOLO crop）
```

标准路径不创建 `propose_regions` / `roi_screen` / 普通 `hybrid_scan`；这些工具已移除。

当某类 required feature 在同一样本的全部视野中均未覆盖时，runtime 为可补查视野提供一次：

```text
feature_scan fallback（旧配置为 hybrid_scan）
features = missing_required[:fast_fallback_max_features]
max_locate_calls = fast_fallback_max_locate_calls
```

当前值：

```text
fast_fallback_max_features = 2
fast_fallback_max_locate_calls = 6
feature_scan_tile_policy = full
```

fallback 完成后：

```text
4 tile 有 crop → 合并 → classify 新增 crop
4 tile 全空 → 该 feature 结束，不重试
```

## 3. 候选与 P0

- 每图五折各自 Top-3，映射去重后形成候选兴趣。
- B 规则候选池不被 A 截断；A 只决定重点补查方向。
- `adaptive_v2` 的 P0 缺口只是建议，不是强制路线。
- 模型可以提出、调查、暂停、撤销、恢复假设；状态不是证据。
- 模型可以覆盖软停止建议，记录理由或未说明原因，不为补理由重复请求模型；硬预算、身份、标定、质量和证据版本仍由程序校验。

## 4. required coverage

fast 模式按样本合并各视野的有效分类。同一特征在任一视野检出即可覆盖，逐图缺失仅供审计。样本级字段如下：

```text
required_features
required_all
missing_required
required_useful
```

不是：

```text
只要有一个 feature_id 就算该图覆盖
```

例如：

```text
YOLO 检出 fiber
required = needle_crystal
→ missing_required 仍包含 needle_crystal
→ 仍允许一次 GLM fallback
```

停止判断分为：

```text
finish         正式结论
request_review 人工复核
```

`missing_required` 非空时：

```text
→ 作为调查建议，不因其他候选缺口自动禁止结束
→ 原规则未授权时不确认，finish意图同轮转review
→ request_review始终合法
```

`request_review` 的意义是：

```text
模型承认证据不足
而不是模型声称已经确认
```

因此 coverage 不完整不能拒绝 review。

当前 `stop_decision`：

```text
can_finish
can_review
recommended_exit = finish / continue / review
blockers[] = {code, actionable, hard, advisory_only, reason}
```

不具备确认资格时不提供finish；模型仍提finish则同轮转review，不再反复拒绝；<br>
没有合法动作时推荐 review。

如果 fallback 全空，仍保留：

```text
insufficient_evidence
unknown
```

不把“没扫到”改写成“阴性”。

## 5. 身份完整性门

```text
identity_required crop
+ 尚未分类
+ det_score < 0.8
→ identity_pending
→ 禁止该对象segment/measure直至身份合格
→ 其他合法对象和review仍可选择
```

高分：

```text
det_score 只用于定位优先级
→ 仍必须先 classify/身份确认
→ 未确认不得进入 IGM/测量
```

`box_quality=blank` 不再无条件阻断高分 crop；低分 blank 仍阻断 segment。

## 6. classify

`classify_crops_batch` 与 `classify_target`：

```text
CNN batch 全部待分类 crop
→ top1_prob >= cnn_threshold、熵低、非 other
   → source=cnn
→ 否则 GLM classify 兜底
```

GLM 是低置信兜底；required crop 的 YOLO 复核只在同类命中时融合，YOLO 未命中时保留 GLM。

## 7. 暂定排序与 required_states

`WorkflowRuntime.summary` 额外提供：

```text
workflow.required_states[]
  candidate_id / display / required_states[] / pending[]
workflow.discriminating_gaps[]
  candidate_id / feature_id
```

`output.json.top_candidate.selection=provisional` 只用于 tentative 首选；正式确认仍看 formal verdict。

`output.json.provisional` 只读当前有效 evidence snapshot，使用：

```text
VERIFIED_MATCH     1.0
DETECTED_PENDING   0.5
PARTIAL_MATCH      0.25
CONFLICT            0
```

规则：

```text
同一 crop 只取一个最佳 classification
同一判据只计一次
0.5/0.25 不进入正式 support_count
formal_verdict 不由 provisional 改写
```

Agent 用 `required_states` 判断：

```text
已检出待核验 → 复核该实例/换清楚视野
部分匹配 → 补关键形态
冲突 → 记录冲突，继续区分候选
未检出 → 保留未知，按预算补查
```

## 8. 停止与 stop_decision

`assess` 每轮给出：

```text
can_finish
can_review = true
recommended_exit
blockers[]
```

判断：

```text
can_finish=true
→ finish 可选

can_finish=false, 有 actionable blocker
→ recommended_exit=continue

can_finish=false, 无 actionable blocker
→ recommended_exit=review
```

`finish` 是正式结论，`request_review` 是证据不足出口；<br>
两者不能混为一谈。

常见停止码：

```text
no_legal_actions
budget
deadline
planner_request_review
runtime_request_review
no_progress_after_advice
```

停止码不是诊断。正常停止后：

- 固定证据版本；
- 生成 `final_evidence.json`；
- 生成 `final_assessment.json`；
- 生成 `report.md`；
- 保留 `review_required`。

`pilot_empty` / fallback 全空只表示该轮 tile 没找到，不等于目标不存在。

`no_progress_after_advice` 表示建议停止后仍连续两次无进展执行；不同意建议本身不触发它。有新进展可继续，假设/文件名改变不能单独清零。旧override_exhausted只保留为历史日志解释。

## 9. 收尾与回退

```text
agent.workflow.final_assessment_llm=true
```

默认预留 finalization 预算、一次文本调用和 30–45 秒。末次调用不发图、不调用 MCP、不新增证据。

如果文本失败、引用非法、证据包超限或硬截止：

```text
→ 程序化 final_assessment
→ 记录 method / model_failure / usage
```

模型倾向不等于原规则确认；`fused_score` 不等于准确率。

## 10. 共享搜寻账本

同一个图像问题不因候选不同重复调用：

```text
source SHA + feature + actual question + scope + tool/model/KB version
→ 一次观察
→ candidate_ids 多个消费者
```

候选名不是视觉请求身份。<br>
共享结果只复用已有观察，不把空结果改写成“不存在”。

D2：自主路径先按taxonomy提出通用特征存在性问题，各候选共享其物理观察；候选形态/量纲差异仍作为独立区分问题。`eligibility_projection`在下一轮显示可引用支持、局部反证、诊断线索及不合格量纲；与收尾共用资格函数，不新增独立审查模型。高IoU/包含只显示ambiguous，Agent可选调查或复核，不自动合并或改变裁决。

摘要省略的内容可通过`read_evidence_detail`分页读取；完整五折Top-K并集保留。详情读取仍是可选动作，菜单截断保留一个展开入口，不能据此声称总规划token下降。详见[12 D2交付与验收](12_D2交付与验收.md)。

## 11. Reflection

- 任务内 Reflection：连续无收益或动作失败时生成结构化提示卡，只调整后续策略；
- 离线 Reflection/LangMem：显式命令生成、回放、验证、发布；
- 任务反思不能修改工件、尺度、判据、权限或资格。

维护说明｜v7.0｜2026-11-17：同步 stop_decision、review 出口、共享账本、语义终止和 2400 秒预算。

## 12. EFF-001：反思必须区别策略、进展与结论

physical-question ID绑定源图/特征/用途/语义范围，不因scan→classify阶段转换误记switch_question。输入归因在执行前冻结，crop被撤销也能审计。evidence表示可采信事实变化，capability表示可继续核验的有效工件，diagnostic表示已评估某输入但无支持；退出建议采纳单列，不制造阳性。已investigating候选的重复激活、排除已不可执行动作标记为no-op。effective不是因果收益或跨任务自进化。

补丁仍和正常ReAct请求一起提交；错误的可选假设、补丁或parallel_question_id不废弃已合法主动作，不为修可选字段额外调用模型。模型可选择两个独立presence同时执行，亦可只选一项或review；身份目标不等于量纲目标。默认semantic_execution=false保持单步，实验开启后语义节点每次仍校验真实依赖并可回交ReAct。详见[15](15_调查效率与反思收益优化.md)。

变更记录：v7.1｜2026-11-17｜语义归因、分轴收益、no-op与模型授权并发。

## 13. PLANNER-CHOICES-001：将执行意图放在主选择中

模型用decision.kind选择A单动作、G实例目标或Q问题组，三者同级；review仍属于可选A动作。不是程序从一个动作推断模型也授权了目标或伙伴。目标逐项晚绑定，任一资格/输入/预算问题回交ReAct；问题组只含当前可见合法presence/scene，不推断未来调查。实际菜单见planner_offer，模型选择模式见thought.execution_choice；全部合法动作或旧timeline不证明实际送模可见性。

语义表的planning_saved_upper_bound扣除已有自动测量，失败可无节省；目标不减少必需视觉调用。共同消费者仅说明一次观察可共享，不能把共享存在性当作形态/尺寸区分。具体真实14轮原因与接口见[16](16_主选择协议与规划次数分析.md)。

变更记录：v7.2｜2026-11-17｜自主选择单步/目标/问题组，不强制并行。

## 14. CANDIDATE-AUDIT-001：质量先于效率

ReAct必须看见逐折候选并集、暂停/未映射及各required/supporting的状态；Top1满足不能替代候选组分析。`stop_advisory.recommend`与`stop_decision.recommended_exit`来自同一决定，缺口存在且有动作时建议continue，无动作时建议review，仍允许模型覆盖建议。adaptive_v2仅限制完整确认的资格：candidate_audit_incomplete会使无资格finish同轮投影为review，不强制追加付费调查或重问；review始终可选。

解除不同对象之间的错误依赖后，另一个crop待分类不阻断本视野独立特征补扫；同一对象分割/测量的身份、QA、标定与预算保持。模型仍可选单步、实例目标、独立观察组或review，没有写死候选顺序。暂停不删除阳性，失败/未执行不是阴性，多图局部阴性不外推。详见[17](17_候选审查完整性与效率边界.md)。

变更记录：v8.0｜2026-11-17｜候选审查与停止建议一致，不以低规划数作为目标。
