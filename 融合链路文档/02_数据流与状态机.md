# 02｜数据流与状态机

同步版本 v4.0｜2026-11-04。用于按运行工件定位请求停在哪一段。

```text
输入绑定 → A 五折推理 → 路由 → WorkflowRuntime
                                      ↓
                assess → think → act → assess
                   ↓        ↓
                  END      END
                                      ↓
                      最终规则裁决和融合报告
```

1. A 一次前向拿到每折概率。适配器落盘 `a_prediction.json`。平均榜交给现有路由，`shadow` 只记录建议。
2. 工作流从原图、部分工件或已有 run 建立证据版本。规划端和 MCP 用同一份 A 文件及候选配置构造候选兴趣。
3. `assess` 重评分和更新动作。 `think` 选择合法动作或停止。 `act` 执行、校验、提交，记录证据变化及实际收益，再回到 assess。
4. 阶段依赖通常为检测 → crop → 分割 → mask → 测量。物理尺寸需要可信标定；独立存在性补查不等待测量。标定成功无法替代目标框。
5. 无合法动作、截止、步数或否决上限耗尽时收尾。失败或未观测保持未知。

动作调用前预约预算。同依赖指纹去重；重算工件写入独立动作目录，提交前核验依赖与截止状态。异步执行和状态刷新不等于任务自动恢复。详见 [05 决策](05_决策协议.md)和[06 硬约束](06_硬约束与回退.md)。
