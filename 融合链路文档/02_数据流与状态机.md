# 02｜数据流与状态机

同步版本 v5.0｜2026-11-08。用于按运行工件定位请求停在哪一段。

## 1. 总体状态

```text
输入绑定
→ A 每图五折
→ 路由
→ WorkflowRuntime
→ assess → think → act → assess
→ decide / fusion / final_assessment
```

## 2. 输入与 A

1. `multi-view` 校验 manifest、SHA256、路径范围和重复。
2. 新 case 复制中性 `view_01...`，建立空 A 缓存。
3. 每张图独立五折推理，落盘 `a_prediction.json`。
4. 每折各自 Top-3 进入 Agent 候选兴趣；平均榜只作路由和对照。

## 3. B 阶段数据流

```text
detect_fov_initial
→ propose_regions
→ roi_screen / roi_screen_batch
→ locate_feature
→ classify_target
→ segment_instance
→ measure_instances
```

| 阶段 | 产物 | 不变量 |
|---|---|---|
| detect | YOLO 特征框、crop | 框属于特征，不是药材 |
| propose | 每图 6 个 ROI、线纹理分 | 本地计算，不是模型证据 |
| screen | ROI 排名（不返回框） | 同图已有 screen 不重复 |
| locate | 特征候选框、`det_score` | 同一 `(image, ROI)` 不重复 |
| classify | 身份标签、置信度、reason | 低分 identity 先 classify |
| segment | mask、IGM 状态 | 需合法 crop/身份/标定 |
| measure | 物理尺寸 | 需合格 mask 和用途资格 |

## 4. 身份门

```text
identity_required crop
+ 尚未 classify
+ det_score < 0.8
→ identity_pending
→ 只允许 classify 最高分 crop
→ classify 尝试后，才允许继续
```

classify 记录：

```text
done / failed / pending
```

任一存在即不再无限重试。

高分绕过：

```text
det_score >= 0.8
→ locate_override
→ 可进入诊断性 IGM/测量
```

## 5. 批量 screen

```text
缺失 screen 数 > 1
且 screen_concurrency > 1
→ screen:batch 目标
→ roi_screen_batch 动作
→ ThreadPoolExecutor 并发 worker
→ 收集多个 screen.json
→ WorkflowSession 一次提交
```

并发只发生在 worker；证据版本和 `operations.json` 不在 worker 中并发写。

## 6. 预算与停止

- 初始化：`N + initialization_reserve`；
- locate：`max(4, per_view*N + reserve)`；
- screen：`screen_concurrency`；
- 规划/观察/API/资源：固定安全上限；
- `max_parallel=2` 仅独立观察。

停止原因：

```text
no_legal_actions
budget
deadline
planner_request_review
runtime_request_review
override_exhausted
```

停止码不是诊断；正常停止仍生成 `final_evidence.json`、`final_assessment.json` 和报告。
