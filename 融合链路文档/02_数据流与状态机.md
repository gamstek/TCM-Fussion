# 02｜数据流与状态机

同步版本 v6.0｜2026-11-10。用于按运行工件定位请求停在哪一段。

## 1. 总体状态

```text
输入绑定
→ A 每图五折
→ 路由
→ WorkflowRuntime
→ assess → think → act → assess
→ decide / fusion / final_assessment
```

## 2. 输入与 A

1. `multi-view` 校验 manifest、SHA256、路径范围和重复。
2. 新 case 复制中性 `view_01...`，建立空 A 缓存。
3. 每张图独立五折推理，落盘 `a_prediction.json`。
4. 每折各自 Top-3 进入 Agent 候选兴趣；平均榜只作路由和对照。

## 3. fast 路径数据流（当前默认）

配置：

```text
fast_yolo_stage2 = true
```

```text
detect_fov_initial（每图 YOLO）
→ 所有 YOLO crop 保留
→ classify_crops_batch / classify_target：CNN 批量或单实例分类全部 crop
   ├─ top1_prob >= cnn_threshold、熵低、非 other → source=cnn
   └─ 否则 GLM classify 兜底
→ coverage：同一样本的任一视野是否已有该 required feature 的有效分类
   ├─ 有：calibrate_fov → segment_instance → measure_instances
   └─ 无：一次 hybrid_scan fallback
```

fallback：

```text
features = missing_required[:fast_fallback_max_features]
max_locate_calls = fast_fallback_max_locate_calls
feature_scan_tile_policy = full
```

```text
每个 feature 并发跑最多 4 个 tile
→ 任一 tile 有 crop：合并进 evidence
→ 4 个 tile 全空：该 feature 返回空，不重试
→ 总 locate <= max_locate_calls
```

fallback 结果仍走：

```text
classify_target（CNN batch，新增 crop 重新计算）
→ coverage required
```

同时生成：

```text
output.provisional
  classification → 暂定排序
workflow.required_states
  → Agent 补查清单
```

暂定排序不写 formal score，不改变正式 support_count。

## 4. 非 fast 兼容路径

```text
detect_fov_initial
→ propose_regions
→ roi_screen / roi_screen_batch
→ locate_feature
→ classify_target
→ segment_instance
→ measure_instances
```

`screen_max_rois=4` 只限制 screen 输出；`propose_regions` 仍可产生 192 个候选区域。

## 5. 阶段产物与不变量

| 阶段 | 产物 | 不变量 |
|---|---|---|
| detect | YOLO 特征框、crop、`px_per_um`（可空） | 框属于特征，不是药材；标定失败不丢框 |
| propose | 每图 ROI、线纹理分 | 本地计算，不是模型证据；fast 默认不跑 |
| screen | ROI 排名（不返回框） | 同图已有 screen 不重复；fast 默认不跑 |
| locate | 特征候选框、`det_score` | 空结果不裁 crop；ROI/框有最小尺寸 |
| classify | 身份标签、置信度、reason | CNN batch 先行，低置信 GLM 兜底 |
| segment | mask、IGM 状态 | 需合法 crop/身份/标定 |
| measure | 物理尺寸 | 需合格 mask 和用途资格 |

## 6. 身份门

```text
identity_required crop
+ 尚未 classify
+ det_score < 0.8
→ identity_pending
→ 只允许 classify 最高分 crop
→ classify 尝试后，才允许继续
```

高分绕过：

```text
det_score >= 0.8
→ locate_override
→ 可进入诊断性 IGM/测量
```

## 7. required coverage 与停止

`coverage` 返回：

```text
useful / useful_all / missing_useful
required_features
required_all
missing_required
required_useful
```

fast 模式：

```text
finish_veto 使用 missing_required
coverage guard 使用 missing_required
```

停止码：

```text
no_legal_actions
budget
deadline
planner_request_review
runtime_request_review
override_exhausted
```

`pilot_empty` / `feature_scan=0` 只表示这次 tile 没找到，不等于目标不存在；仍须保留 unknown。

## 8. 预算与失败

```text
max_initializations = N + initialization_reserve
max_locate_attempts = max(4, per_view*N + reserve)
```

固定安全上限：

```text
max_planning=60
max_observations=40
max_api_calls=200
max_resource_units=400
```

关键失败边界：

- `detect_fov_initial` 的 YOLO 成功、自动 scalebar 失败：保留框，`px_per_um=None`；
- 所有视觉工具失败：记录 service failure，不按阴性处理；
- fallback 全空：记录空结果，不重复同一个 fallback 目标；
- 正常收尾仍生成 `final_evidence.json`、`final_assessment.json`、`report.md`。
