# 04｜工具清单

同步版本 v7.0｜2026-11-17。技能描述指导选法；ToolSpec 与运行时约束授权、参数、目标、预算和结果校验。

## 1. 工具分层

| 层 | 工具 | 作用 |
|---|---|---|
| 只读 | `read_evidence`、`read_evidence_detail`、`read_action_catalog`、`list_features`、`query_criteria`、`read_scale`、`list_fovs`、`criteria_diff`、`list_artifacts`、`read_artifact_status`、`read_quality` | 查已有证据、完整动作目录、判据、标定和 QA；不新增视觉证据 |
| 全图检测 | `detect_fov_initial` | YOLO 全视野特征检测；标定失败只置空尺度，不丢框 |
| 区域检测 | `detect_region` | 已有 ROI/crop 的局部 YOLO |
| 标定 | `calibrate_fov` | 生成 `px_per_um` 尺度 |
| 通用扫描 | `feature_scan` | 按 feature 做 tile 扫描；支持 `full` / `prescreen` |
| 混合扫描 | `hybrid_scan` | 并发 YOLO + 多特征 GLM；仅 `legacy_bundle` 旧配置 |
| 定向定位 | `locate_feature` | GLM 在 ROI 中找指定特征框 |
| 身份复核 | `classify_crops_batch` / `classify_target` | 批量/单实例 CNN 初判；高置信直接采用，低置信由批量动作登记 pending，单实例可 GLM 兜底 |
| 分割 | `segment_instance` | 生成 mask / IGM |
| 测量 | `measure_instances` | 从合格 mask 和尺度生成物理尺寸 |

`classify_crops_batch` 提供逐实例批量 CNN 动作，`classify_target` 保留单 crop 路径，两者共享 CNN 缓存。

当前模板的 GLM 兜底可在同一张送模图内加一对人工确认的形态示例。目标区保留原生分辨率，未报告所属类别的可见结构和部位时记“身份待定”。对照索引及回退条件见[融合配置](../config/README.md#单实例视觉身份复核)。

当前执行边界：

```text
classify_target：同一 crop 只自动尝试一次；不可判/other 不自动重试
segment_instance：同一 crop/高 IoU 区域 review/failed 后不自动换 ROI 重试
request_review：证据不足时可收尾，不要求补齐全 required
```

## 2. fast 模式实际工具顺序

```text
detect_fov_initial
→ 自动 classify_crops_batch
→ top required 已验证 crop：
     segment_instance
     → auto measure_instances
→ 按相关判据选择是否进行 scene_check
→ 若缺 required feature：
     feature_scan / presence fallback（按模板，有限）
     → 新增 crop 分类
     → 重新 coverage
→ 候选组 required 单次核验（如有）
```

fast 模式默认不创建：

```text
propose_regions / roi_screen（工具已移除）
普通 hybrid_scan（仅 legacy_bundle 旧配置创建）
```

## 3. 类别来源与分工

```text
Plan A → 药材种类
YOLO → 显微特征类别 + 框
GLM locate → 指定特征候选框
CNN stage2 → crop 的 14 类特征
GLM classify → stage2 低置信/other 的身份兜底
```

- YOLO 不输出药材结论。
- CNN 不生成框，不能替代 locate。
- GLM locate 不负责最终分类，必须由 stage2/GLM classify 复核。
- GLM classify 不重新定位；required crop 的 YOLO crop 复核只是辅助。

## 4. 前置条件

| 工具 | 前置 |
|---|---|
| `detect_fov_initial` | 原图已绑定 |
| `detect_region` | 合法 ROI 或 crop |
| `calibrate_fov` | 原图/标尺可用 |
| `propose_regions` / `roi_screen` / `roi_screen_batch` / `needle_scan` | 已随标准路径移除，不再注册 |
| `feature_scan` | 原图已绑定；`feature_scan_enabled=true` 且 feature 合法 |
| `hybrid_scan` | 原图已绑定；`hybrid_scan_enabled=true`；A 候选提供 missing required feature；fast 中仅 fallback |
| `locate_feature` | screen top-k 或 fallback ROI |
| `classify_target` | 合法 crop；fast 中所有 YOLO/GLM crop 都可分类 |
| `segment_instance` | crop 身份满足、尺度可用；同区域 review 后不重复自动重试 |
| `measure_instances` | 合格 mask、标定、用途资格；无有效 mask 不伪造 μm |

## 5. locate 质量约束

```text
locate_min_roi_side = 256
locate_min_box_side = 90
locate_expand = 1.5
```

- ROI 小于 256 时围绕中心扩展；
- tight box 小于 90 时扩展，保留 `source_tight_bbox`；
- 无目标必须返回 `{"objects":[]}`；
- 空结果不裁 crop；
- 同 ROI 的重复返回做 NMS；
- 任何 `identity_required` crop 未通过分类/身份确认时不得进入 segment/measure；
- 高分 `det_score` 只影响定位优先级，不绕过身份门；
- `blank/low_detail` 只保留分类/待核验，不进入诊断性 segment。

## 6. tile policy

```text
feature_scan_tile_policy = full
fast_fallback_max_locate_calls = 6
```

`full`：

```text
4 个 tile 全部并发
→ 任一 crop：合并继续
→ 全部空：立即返回空，不重试
```

`prescreen`：

```text
先扫纹理最强 pilot
→ pilot 空：停止该 feature
→ pilot 有 crop：继续剩余 tile
```

`fast_fallback_max_locate_calls` 限制一次 fallback 的总 locate 数。当前默认 `2 feature + 6 cap`；`feature_scan_concurrency=2`。

## 8. 旁路审计

`feature_audit` 在调查结束后读取同一个有效证据快照，按已登记的裁图 ID 绑定分类和 mask。YOLO 初检、通用补扫、单体及批量分类都通过已提交的快照工件纳入审计。

```text
feature_audit/feature_audit.json
```

新报告使用 `feature-audit/v2`。空列表或不设 `feature_audit_features` 时覆盖快照中的有效裁图，非空列表按裁图的特征过滤。报告字段包括以下内容。

```text
evidence_version
candidate 的 feature_id / classified_feature_id / target_score / negative_margin
high_score_unclassified / low_score_unclassified / classification_unresolved
mask 的 connected components / skeleton / merged
issues 中的工件 ID 和读取或摘要异常
```

分类标签与当前裁图特征一致时，`target_score` 使用该分类分数。改判其他特征时记录其类别，拒绝或不可判保留为未解决。旁路报告不改变 `decide`、证据资格或原测量。旧运行中的 v1 报告保留原样。
