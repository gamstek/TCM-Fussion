## 3. 组成部件与控制流

新增`lib/planning_choices.py`仅提供视图和解码，不执行工具、不替换ToolSpec或证据契约。

```text
当轮实际可见合法动作
→ attach：关联实例目标/独立问题/候选消费者
→ model_view：A/G/Q短编号及一致主选择
→ ReAct自主选择单动作、目标、问题组或review
→ decode：只展开明确授权 → 现有权限/预算/依赖校验
→ 原MCP执行/语义晚绑定/父循环顺序确认
→ 原规则、分轴反馈、Reflection → 下一轮ReAct或收尾
```

没有枚举所有问题对，没有给候选写固定调查顺序；只允许当前合法presence/scene、最多两项。依赖第一项结果才能决定第二项时选择单步。问题消费者共用一次观察，但共同存在性不能代替各自形态或量纲判据。

## 4. 真实接口与配置

`attach(runtime, context, *, can_pair)`关联当前可见动作、KB定量用途和目标；`model_view(context)`返回送模副本与编号反解；`decode(reply, context)`校验并解码明确选择；`audit(context)`保留实际菜单。无新增依赖、MCP权限或配置开关；semantic_execution仍需显式true，标准模板保持false。

主回复三选一：

```json
{"decision":{"kind":"action","action_id":"A编号"},"decision_summary":"简短理由"}
```

```json
{"decision":{"kind":"instance_goal","goal_id":"G编号"},"decision_summary":"需要的合格量纲"}
```

```json
{"decision":{"kind":"observe_questions","question_ids":["Q编号","另一Q编号"]},"decision_summary":"为何两项都值得查"}
```

编号来自本轮真实菜单，不是示范编号默认执行。G绑定入口动作、实例、特征、用途、候选消费者及规划节省上界；不是API节省承诺。Q按当前可见问题列出，不生成未来target。旧action_id/semantic_goal/parallel_question_id保留兼容，主选择不能同时使用新旧两种格式。

## 5. 失败与降级

无效主选择不猜首项。观察组只按当前短编号或当前canonical_question_id精确解析；部分失效时仅执行原请求中明确选过且仍合法的项，记录choice_partially_preserved并在selection_feedback反馈，不代选其他问题、不为纠正附加项付费重问。全组无合法项或新旧主选择矛盾则拒绝。选择后再次检查权限、真实前置和预算；目标遇身份、mask review、标定、量纲资格、输入变化或截止立即回交ReAct。仅身份目标不能以分割/测量作为入口。两路观察失败各自记账，unknown不转阴性，成功伙伴保留；同源观察不按独立样本计支持。可选补丁/假设字段错误仍保留独立合法主动作。

planner_offer新增实际送模A/G/Q表、预算和上下文摘要指纹；thought.execution_choice记录模型选择的模式。planning_menu也改记实际展示动作，而非全部choices。历史context_profile只有字节数，不应冒称它保存了完整菜单。审计仅记录决策摘要和菜单，不保存思维链、密钥或图像载荷。

## 6. 验收与效益边界

测试接入现有selftest：真实LLM序列化/编号解码对拍、真实LangGraph依赖执行、单步/review保持、同步屏障验证独立观察重叠/部分失败、预算、非法编号、review mask、身份目标入口及简化verification菜单关联。可控fixture通过不等于真实模型会选择这些模式。

不能预设14次降到固定次数，更不能为证明并行有效强制配对。目标/问题组选中率、有效证据、规划次数、实际usage、墙钟时间及误确认应分别报告；最终以本批verification.json和新真实case为准。已有自动测量节省不得重复计入，生成两张mask仍要付两次必要工具成本。
