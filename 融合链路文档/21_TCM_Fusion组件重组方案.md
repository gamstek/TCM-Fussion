# TCM_Fusion 组件重组方案

2026-11-18。范围为 TCM_Fusion 源码、测试、配置说明与开发文档。根重构方案只登记结构取舍与完成证据。

## 目标和边界

以开发任务组织源码。每个组件说明入口、输入输出、调用方与测试。文件头保留功能说明、主要定义、关联三段。功能说明写明接收的数据、实际处理与产物，指出该文件负责的验证和副作用。测试说明同时标明真实执行部分和替身。

保留 `cli.main`、`cli.offline`、子进程模块名、MCP 工具名、运行配置口径及原 B 规则。原图、权重、知识库、跨阶段契约、历史运行目录与格式作为重组的输入基线。行为修正限定于下表。旧提示发布文件含代码签名，移动后会触发现有重验门，使用原版本读取历史工件或重新验证发布。历史回放仍沿用来源路径和摘要约束。

## 组件和依赖

| 目录 | 职责与主要调用关系 |
| --- | --- |
| `lib/application` | 用户入口的任务组装、A/B 分流、调查和收尾。调用 Agent、MCP、工作流与交付组件。 |
| `lib/agent` | ReAct、规划视图、动作选择、任务内反思，以及已发布提示/模拟经验的读取。消费证据、候选和工具接口。 |
| `lib/mcp` | stdio 适配、上下文恢复和工具协议映射。连接 workflow 与 tools。 |
| `lib/tools` | 工具契约、权限、工具实现和观察后端。采用宿主提供的运行时，保持对 workflow 的结构化接口。 |
| `lib/workflow` | 绑定原图和工作流，维护候选动作、阶段操作与提交，协调 A/B 原入口调用。 |
| `lib/vision` | 图像分块、特征提示、框质量、定位、CNN/YOLO 与视觉审计。复用目标检测已有类别表。 |
| `lib/evidence` | 工件索引、证据版本、实例标识、用途资格与阶段录制。 |
| `lib/decision` | 候选范围和比较、分流、A/B 融合、收尾与交付投影。 |
| `lib/runtime` | 路径转发、文件读写、互斥、进程、调用预算、签名监控与共用校验。 |
| `lib/offline` | 数据划分、评估、回放、拟合、优化与发布。可以调用正式组件。 |
| `tests` | 按组件分组。跨组件回归集中在 integration，共用替身和构造器在 support，录制输入在 fixtures。 |

在线执行依赖发布工件读取器以及正式的工件录制函数。离线命令依赖这些相同接口。测试使用调用方显式传入的替身，真实工作流拒绝模拟视觉后端。MCP 的模拟上下文保留给协议自检，工件来源仍以 simulation 标志区分。

直接依赖按从上游到下游的顺序列在 [源码导航](../lib/README.md) 的各组件页面。关键链路如下。

- 应用层连接 Agent、MCP、工作流和决策。MCP 绑定工作流与工具箱，工具箱消费已注册的运行时接口。
- 工作流消费视觉、决策、工具和证据。决策消费证据、工具 schema 与视觉描述。Agent 从决策、证据和工具读取规划所需的信息。
- 工具和证据使用运行基础设施。离线组件可以调用正式组件。组件级导入环和线上对离线或测试包的导入由 selftest 检查。

各组件 README 列出文件清单。旧文件名继续用于迁移后的模块名，包括测试文件。例外是重复的 det_dataset 模块由目标检测层直接提供，以及下表列出的职责提取。

| 原模块 | 提取后的所有者 |
| --- | --- |
| `prompt_optimization` | `agent/prompt_release` 负责候选约束、运行上下文和版本读取，优化与发布仍由离线模块负责。 |
| `reflection` | `agent/reflection_memory` 负责经验格式和模拟读取，任务内反思仍由 `reflection_controller` 负责。 |
| `confidence_gate` | `decision/confidence_contract` 提供共享校验与数值变换，`decision/routing_policy` 读取发布策略并判定。 |
| `workflow_replay` | `evidence/stage_recording` 记录阶段工件摘要，离线回放消费该记录。 |
| `agent_tools` | `tools/simulation` 提供显式模拟后端，正式工具箱检查运行模式。 |
| `tool_registry` | `runtime/schema` 提供通用校验和可选定位响应约束，注册表保留权限和 handler 绑定。 |
| 用例之间共用的阶段、工作流和交付输入 | `tests/support/workflow_fixtures` 与 `tests/support/result_builders`。测试类仅在实际用例模块中发现。 |

## 复核和取舍

| 问题 | 处置与验证 |
| --- | --- |
| 延迟导入成环 | 提取提示发布校验、模拟经验读取、阶段录制与置信校准共用原语。按运行职责检查所有 import，包括函数体。 |
| 真实路径接受模拟观察 | 在工具箱构造时检查运行模式，覆盖真实 runtime 加模拟 backend 的反例。 |
| 初始化/运行异常与监控退出 | 启动签名纳入失败状态。运行失败或取消时关闭资源并发出取消信号。签名无法读取时登记诊断并取消。 |
| stage2 适配器与启动钩子路径 | 直接对适配器源码文件取指纹。同步 worker 启动钩子的包内位置并验证真实子进程。 |
| 签名漏技能资产 | 纳入技能注册表和技能正文。验收检查导入、工件签名和发布上下文。 |
| 工具账本与 transport 耦合 | 新工作流的 MCP 与 local 使用同一任务内路径。历史/显式模拟上下文保留既有规则。 |
| YOLO 路径缓存 | 同路径内容变化时重新加载，保留每次运行的模型身份。 |
| 冗余参数和兼容 schema | 核实字段是否参与行为。示例审计专用超时接入执行预算。非生效字段从当前模板移出，继续兼容旧配置。分块成像策略单独评估，避免把目录迁移当成算法变更。 |
| 分类类别表复制 | 核对与项目目标检测共享实现的函数结构后复用同一权威。 |
| 用例发现与依赖错位 | 提取共享测试数据和构造器。按用例身份而非仅凭计数对账。所有测试保留在原 selftest 发现范围内。 |

旧字段和接口需有消费者证据才能删除。审查覆盖普通/延迟导入、`mock.patch`、子进程 `-m`、配置字段拼接、技能和工具注册、资产加载与历史记录。大文件在此次按职责归属，后续按可独立验证的边界继续拆分。

| 配置或工件 | 当前行为 |
| --- | --- |
| `feature_scan_tile_size`、`feature_scan_overlap` | 旧配置继续通过 schema。当前均匀分块由原图尺寸和分块上限决定，参数从新模板移除。 |
| `feature_scan_tile_policy`、`feature_scan_concurrency` | 后端通过组合键读取，保留 `full`、`prescreen` 与并发限制。 |
| `feature_scan_enabled` | 默认开启。设为 false 后移除逐类补扫和旧配置的合并补扫动作。 |
| `hybrid_scan_enabled` | 用于读取历史配置。补扫模式按 `fast_recovery_selection` 和合法工具配置决定。 |
| `auto_prepare_stage`、`auto_required_measurement` | 旧字段继续兼容。模型按合法菜单选择调查，同一对象合格分割后的自动测量仍由 `auto_measure_after_segment` 控制。 |
| `cnn_other_fallback` | 兼容旧配置。CNN 的 other 不作为身份确认。 |
| `feature_audit` | 通用特征旁路审计开关。指定 `feature_audit_features` 可限定审计类别。 |
| `image_exemplar_seconds` | 审计进程超时取该值与阶段剩余时间上限的较小值。缺省沿用通用上限。 |
| 历史路径和签名 | 旧文件按原内容保留。代码签名随新包路径变化，历史任务的续跑与提示发布继续受既有指纹校验。 |

## 验收与回滚

1. 记录迁移前运行环境和既有失败。移动前核对每个文件的落点和跨目录消费者。
2. 类别表、共享提取和机械迁移采用 AST 或固定输入对拍。需要改变行为的缺陷用反例回归。校对工具名及 worker 路径，确认新包均有 README 和轻量初始化。
3. 从项目根运行 `.venv\Scripts\python.exe -X utf8 -m TCM_Fusion.cli.main selftest`，包含原 B 三套。对照发现的用例名称和跳过原因。核实离线 CLI 可导入，MCP stdio 与本地 worker 在各自解释器边界可启动。
4. 原任务文件保持可追溯，测试使用独立目录和可控输入。验收结论来自本地回归和工件契约。
5. 回滚以源码提交为单位，活跃任务应在原签名版本完成。对重组后创建的任务保留其源码版本和配置，避免自动复用旧指纹或覆盖旧工件。

本次实施状态与实测结果见本文件末尾及 [修改记录](../修改记录.md)。

## 实施记录与验收

- 源码和测试已迁入组件。路径对账确认 101 个 Python 文件移动，目标检测层的 det_dataset 在忽略模块说明的 AST 对拍中与融合副本一致，现由检测层提供。另有 66 个现役文件在归一化导入路径之后保持相同 AST。
- 569 项既有用例身份全部保留，新增 6 项边界回归。迁移前的 4 个失败分别落在可用环境与行为口径两个方向。两个真实几何工件用例的深层目标路径超出当前 Windows 临时路径限制，改用项目根 results 作为测试进程临时根后通过。另两个涉及共享观察与支持性预算，恢复 adaptive_v2 的通用观察提示，预算仍按同图同特征共用。用例分别断言实际问题键和不允许替换提示，避免将配额键解释为观察等价。
- 完整 selftest 运行 575 项，574 项通过，1 项因缺历史参考 case 跳过。原 B 回归 59、21 和 125 项断言通过。测试进程将 TEMP/TMP 指向项目的 results，将数值库四类线程限制设为 1。
- 三条入口路径分别验证。主与离线 CLI 及七个 worker/server 的帮助均正常。真实原图单视野 dry-run 通过 doctor。实际 MCP stdio 与原几何 worker 的回归通过。
- 独立固定输入确认同路径的 YOLO 权重内容变化会重载，示例审计使用专用超时上限。现有持久化用例仍核对原 B 工件摘要不变。验证范围为本地与离线流程。
