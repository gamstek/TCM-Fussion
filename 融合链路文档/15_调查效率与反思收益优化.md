# 15｜调查效率与反思收益优化（EFF-001）

后续接口以[16 主选择协议](16_主选择协议与规划次数分析.md)为准：目标与观察组已从可选附加字段提升为同级主选择，旧格式仅兼容；以下记录保留EFF-001当时的设计与实测。

## 1. 目的与读者

供链路开发、实验和后续调试使用。针对真实白芍单图中“两个反思补丁没有新增证据、全程408.594秒”的问题，改进进展判断、上下文、模型授权并行与计时。不承诺每次纠正A，也不把反思文字或工具成功等同于鉴别增益。

## 2. 范围与边界

仍由ReAct读取反馈并选择对象、顺序、继续或review。每图五折各自Top-3及候选并集保留；原规则、身份、坐标、QA、标定、量纲资格、精确去重、总预算和截止不放松。`semantic_execution`模板仍为false，显式开启后才可选择实例目标。增加的是两路独立presence的可选执行能力，未完成D4通用DAG、read_set/epoch和事件取消调度；没有多个思考Agent。

## 3. 组成部件

- `comparison_problems.action_question(runtime, action)`：按源图SHA、特征、用途和语义范围产生物理问题ID。扫描后分类同一特征不再自动算“换问题”；实例执行键仍保留输入、方法及参数，不能混用两个工件。
- `investigation_control.progress_state/progress_axes`：区分正式证据、处理能力和有效诊断。新crop属于能力；不可辨认属于诊断，不是阴性。已评估的同一输入和改名不重复算收益。
- `ReflectionController`：执行前绑定问题与输入，防止分类撤销crop后丢失归因；补丁记录实际候选/合法菜单变化。已激活候选、已不可执行动作的重复排除不声称策略增益。退出建议采纳与新增证据分开。
- `planning_context.compact`：判据状态集中到`workflow.criterion_states`；重复镜像删除，资格和来源仍保留。只缩小详细展示窗口，完整候选和显式详情读取保持可达。
- `react_graph`：可选假设元数据错误不废弃独立合法动作；记录模型调用和执行耗时，支持模型选择独立观察伙伴。

## 4. 数据与控制流

```text
当前事实/资格＋候选差异＋问题ID＋实测耗时
→ 紧凑上下文 → ReAct选择动作/停止
→ [可选]第二个独立presence问题 / 同实例语义目标
→ 权限、当前依赖、预算检查
→ 执行 → 父循环顺序确认观察 → 原规则评分
→ 分轴进展＋反思后验 → 下一轮ReAct / 固定证据收尾
```

并发仅在模型明确选择、两个当前合法问题不同且预算可承担时生效。一个失败保留另一项结果；失败仍为unknown。执行独立不表示两份观察是统计独立支持。不并发同实例修复、分割或测量，不自动凑齐视野。

## 5. 接口与配置

`ReflectionController.apply(patch, selected=None, *, legal_actions=None)`保留封闭补丁schema；`record(..., binding=None)`接受主机执行前绑定，不由模型指定来源。

规划回复可附`parallel_question_id`，必须来自当轮`parallel_questions`，且主动作是presence。无效伙伴只记拒绝、保留合法主动作，不额外付费重问。原初检伴随观察接口保持兼容。`max_parallel=2`是上限，不强制并行。

语义目标`verify_identity`只核验身份；`measure_length/width/area`才表示完整的对应量纲目标。工具仍按当前工件晚绑定，模型不生成未来crop/mask ID或具体工具剧本。

## 6. 失败、降级与计时

`planning_timing`覆盖模型调用、worker及解析；`execution_timing`是外层动作跨度，含嵌套自动测量。并行子项和自动测量不可重复累加成墙钟时间。worker的`process_timing.json`和HTTP阶段指标用于进一步定位；发送至响应头包含连接、上传和服务等待，不等于纯模型计算。

MCP保留已知预检错误码：`NETWORK_DISABLED`确定未调用时可记0请求，其他未知计费故障不伪造0。MCP显式透传调用方设置的四种数值库线程变量及TEMP/TMP；不改全局环境。内存紧张时完整回归可能受OpenBLAS分配影响，需记录环境和失败日志，不削弱断言。selftest仅在每例结束回收循环引用，不修改生产GC、预算和阈值。
