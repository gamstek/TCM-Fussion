# 07｜验收与运行

同步版本 v5.0｜2026-11-08。在项目根执行。

## 1. 统一回归

```powershell
.venv\Scripts\python.exe -X utf8 -m TCM_Fusion.cli.main selftest
```

该命令递归运行：

```text
TCM_Fusion/tests
TCM_Fusion/tests/offline
外部原 B 规则/场景回归
```

主链测试和离线功能测试都必须保留；不得通过删除离线断言让清理看似通过。

## 2. 多图预检

```powershell
.venv\Scripts\python.exe -X utf8 -m TCM_Fusion.cli.main multi-view `
  --source-dir <source-dir> `
  --a-python D:/Anaconda/python.exe `
  --dry-run --json
```

dry-run 只：

```text
校验 manifest/SHA256
→ 新 case
→ 复制中性原图
→ 生成配置
→ doctor
```

不调用 A、GLM、YOLO 或 MCP；不证明远端 API 可用。

## 3. 多图真实运行

```powershell
.venv\Scripts\python.exe -X utf8 -m TCM_Fusion.cli.main multi-view `
  --source-dir <source-dir> `
  --a-python D:/Anaconda/python.exe `
  --name 验收测试 `
  --json
```

真实运行会创建新 case、空 A 缓存，并产生 API 费用。

## 4. 验收表

| 要核验的事实 | 工件 |
|---|---|
| 输入哈希、N 张图、空缓存 | `input_proof.json`、`config.json`、`interface_status.json` |
| A 每图五折和每折 Top-K | `a_prediction.json` 的 `view_predictions[].fold_rankings` |
| 模型是否实际选工具及原因 | `agent_trace.json` 的决策、动作、观察、停止 |
| 批量 screen 是否一次提交 | `workflow/operations.json` 的 `roi_screen_batch` 与多个 screen artifacts |
| locate 是否重复 | operation target 的 `(image, ROI)` |
| 身份门是否生效 | `identity_pending` → `classify_target` 顺序 |
| 分类标签 | `output.json.classifications`、classification.json |
| mask/测量 | `workflow/ops/`、IGM、measurement |
| B 裁决与融合 | `fusion.json`、`agent_verdict.json` |
| 停止后研判 | `final_evidence.json`、`final_assessment.json`、`report.md` |

## 5. 结果解读

```text
图片数量已绑定
≠ 每张图都完成全部 B 阶段
≠ 每个 crop 都有身份
≠ 每个身份都产出 mask
≠ 每个 mask 都允许测量
```

必须区分：

- A 先验；
- locate 候选；
- classify 身份；
- IGM mask 质量；
- 物理尺寸；
- 原规则结论；
- 文本倾向。

`fused_score` 是排序分，不是校准正确率；`review_required=true` 和 `insufficient_evidence` 必须保留。

## 6. 当前限制

- `classify_target` 仍单 crop 串行；
- YOLO 仍逐图、默认 CPU；
- locate 未批量并发；
- 固定规划/观察/API/资源上限仍然生效；
- 没有合格身份、mask 或标定时可能没有 μm。

## 7. 失败处理

- 输入校验失败：不创建 case；
- doctor 失败：写 `interface_status.json`，不启动 pipeline；
- 运行失败：在新 case 中保留错误和已产生工件；
- 不用旧 pending 续跑；重试创建新 case；
- 不覆盖历史 `case_9cc59640`。
