# 融合运行结果

本目录接收新任务。历史实测、回放、评估、原目录名和逐案证据入口见 [测试运行总报告](测试运行总报告.md)。

## 目录名

`实测<药材名>_M月D日HH时mm分ss秒` 或 `模拟<药材名>_M月D日HH时mm分ss秒`

示例 `实测龙胆_11月19日14时30分25秒`、`模拟白芍_11月19日14时30分25秒`。

| 字段 | 填法 |
| --- | --- |
| 类型 | `实测` 用于正式真实任务。`模拟` 用于 `--dry-run` 预检、离线模拟、回放或评估。结束状态以运行记录为准。 |
| 药材名 | 用 `--subject` 登记实际药材名。盲测用 `S01` 等中性代号，未知用 `未标注`。无单一药材的评估填写对象，如 `B规则`。 |
| 时间 | 使用北京时间开始时刻，月和日用自然数字，时分秒各两位。完整日期含年份，登记在 `interface_status.json`。 |
| 重名 | 同类型、对象和秒已有目录时，按 `-02`、`-03` 递增，已有工件始终独立。 |

`multi-view`、`five-view` 自动按本格式命名。图数、图号和目的写入 `interface_status.json`、`input_proof.json` 或 `运行摘要.md`。`--purpose` 用于记录目的，默认 `链路测试`。正式结果根使用 `--subject`，旧 `--name` 仅兼容指定至本目录之外的自定义输出。离线工具显式指定 `--out` 或 `--out-dir` 时，按上述 `模拟` 格式填写测试目录。

内部 `runs/fusion_<id>` 用于运行和工件绑定。直接用低层 `run --config` 时，工件路径以该命令的输出为准。

## 运行摘要模板

真跑、回放、评估、重要联调均在 case 顶层写 `运行摘要.md`。失败、中止或需复核时同样填写。标题说明**对象、目的、开始时间和终态**，正文按以下顺序组织：

| 部分 | 至少记录 |
| --- | --- |
| 目的与输入 | 测试问题、对象、图数或样本数、来源和 SHA256；参考标签的用途；同图对照标明顺序及分母。 |
| 版本与边界 | 提交或运行签名、运行 ID、关键开关、实跑或回放、缓存与替身使用情况。 |
| 实际路径 | 真实入口、关键工具及顺序、Agent 实际选择与反馈；跳过、取消或失败的阶段写原因。 |
| 证据、结果与复核 | 新增工件和合格证据、required/supporting 缺口、规则裁决、交付状态、复核要求。 |
| 开销、异常与限制 | 端到端耗时、实际规划次数、分阶段 token 及覆盖条数、停止原因和已知失败。缺项写“未记录”，未执行写“未运行”。 |
| 产物 | 输入证明、轨迹、最终证据和交付的相对链接；回放或实验附对照表及复算口径。 |

从 `input_proof.json` 核对视野，从 `runs/<run_id>/agent_trace.json` 查真实工具顺序，结合 `output.json`、`final_assessment.json`、`final_evidence.json` 区分暂定、正式裁决和复核。归档时将原目录名和运行摘要登记到总报告。用户确认清理旧工件时，先合并逐案文字摘要。
