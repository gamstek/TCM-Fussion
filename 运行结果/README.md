# 融合运行结果

[历史测试总报告](测试运行总报告.md)汇总各案的目的、对象、实际路径、结论及旧 `case_...` 名称。[最新正式 B 规则运行摘要](评估__B规则__30用例__20261119-095522__佐证计分/运行摘要.md)及逐案结果跟随本轮数据保存。示例库 `feature_exemplar_bank_20261109` 是当前配置依赖的运行资产。

## 目录名

`类型__对象__数量与单位__开始时间__目的`

例如 `实跑__龙胆__05图__20261109-1645__Agent补扫` 表示用龙胆的 5 张图做了一次 Agent 补扫测试。新任务名末尾追加 `-<8位十六进制短ID>`，用于同秒运行的隔离。

| 字段 | 填法 |
| --- | --- |
| 类型 | `实跑` 使用真实入口，`预检` 只准备并执行本地 doctor，`回放` 使用已录制工件，`评估` 统计一批输入。查看终态用 `interface_status.json`、`job.json` 或评估报告。 |
| 对象 | 人工登记的药材或测试集名。盲测使用 `S01` 等中性代号。没有明确对象时使用 `未标注`。 |
| 数量与单位 | 入口以通过校验的 manifest 为准，图数至少两位，如 `01图`、`05图`。回放用其来源的输入视野数。数据集评估按实际口径写图、样本或用例，数量来自摘要。 |
| 开始时间 | 新任务使用北京时间 UTC+8，格式 `YYYYMMDD-HHmmss`。历史分钟级或日期级记录只保留可核实的精度。 |
| 目的 | 写正在验证的功能，如 `候选审查`、`身份反思同图`。新入口标签为 1–16 个字符，使用中文、字母、数字或组间单个连字符。默认 `链路测试`。 |

`multi-view` 和兼容入口 `five-view` 自动生成名称。传入 `--subject S01 --purpose 链路验收` 可指定目录标签。盲测也应避免在输入路径和目的中写参考答案。旧脚本可沿用 `--name` 指定整个目录名。内部 `runs/fusion_<id>` 是运行及跨工件绑定，保留程序生成的标识。直接使用低层 `run --config` 时从该命令的输出获取工件路径。

## 运行摘要模板

真跑、回放、评估、重要联调均在 case 顶层写 `运行摘要.md`。失败、中止或需复核时同样填写。标题说明**对象、目的、开始时间和终态**，正文按以下顺序组织：

| 部分 | 至少记录 |
| --- | --- |
| 目的与输入 | 测试问题、对象、图数或样本数、来源和 SHA256；参考标签的用途；同图对照标明顺序及分母。 |
| 版本与边界 | 提交或运行签名、运行 ID、关键开关、实跑或回放、缓存与替身使用情况。 |
| 实际路径 | 真实入口、关键工具及顺序、Agent 实际选择与反馈；跳过、取消或失败的阶段写原因。 |
| 证据、结果与复核 | 新增工件和合格证据、required/supporting 缺口、规则裁决、交付状态、复核要求。 |
| 开销、异常与限制 | 端到端耗时、实际规划次数、分阶段 token 及覆盖条数、停止原因和已知失败。缺项写“未记录”，未执行写“未运行”。 |
| 产物 | 输入证明、轨迹、最终证据和交付的相对链接；回放或实验附对照表及复算口径。 |

从 `input_proof.json` 核对视野，从 `runs/<run_id>/agent_trace.json` 查真实工具顺序，结合 `output.json`、`final_assessment.json`、`final_evidence.json` 区分暂定、正式裁决和复核。旧测试精简前先将摘要并入总报告，只有确认被当前代码、配置或回放承接的工件才作为完整资产保留。
