# Agent 技能卡

这里的五张卡回答“调查到这一步，怎样选动作、怎样解释结果”。紧凑规划上下文默认提供技能 ID 和用途。通过 MCP 的 `list_skills` 可以取得注册映射和各卡的 SHA256，`get_skill` 按已注册的 `skill_id` 读取一张卡的完整正文。[技能索引](registry.json) · [运行时加载](../lib/workflow/evidence_runtime.py) · [MCP 入口](../lib/mcp/mcp_bridge.py)

## 按调查问题选卡

| 当前要回答的问题 | 技能卡 | 能得到什么 |
| --- | --- | --- |
| 现有工件已经回答了哪些判据，还缺哪项资格？ | [evidence_inspection · 查阅已有证据](evidence_inspection/SKILL.md) | 指定候选的事实引用、证据资格、缺口，以及当前可用的调查入口。 |
| 结晶位于哪里，如何排列，哪几个视野还缺场景记录？ | [scene_context · 核验结晶场景](scene_context/SKILL.md) | 按原始视野记录的场景属性，供规则重新评估。 |
| 在这个视野能看见候选判据所关心的特征吗？ | [differential_presence · 核验特征存在性](differential_presence/SKILL.md) | 可以共享的局部定性观察，以及可选的定位线索。 |
| 哪项操作能找到、核验或测量这个实例？ | [workflow_repair · 取得合格实例工件](workflow_repair/SKILL.md) | 已提交的裁图、身份、标定、掩码或测量，也可能得到明确的阻塞原因。 |
| 证据够不够收尾，还需要人复核什么？ | [evidence_stop · 结束调查与复核](evidence_stop/SKILL.md) | 停止意图和依据，由交付层核定候选、证据引用与复核状态。 |

按眼前的问题进入相应技能。已有裁图时可以直接评估测量条件，预算不足时也可以直接申请复核。具体可执行项取决于本轮菜单、工具注册、样品绑定和剩余资源。[工具注册与校验](../lib/tools/tool_registry.py) · [调查主循环](../lib/agent/react_graph.py)

## 编写与维护

每张卡用“技能 ID · 中文职责”作一级标题，首句概括它解决的问题。正文保留四节，篇幅随技能复杂度调整。

| 小节 | 应写清的内容 |
| --- | --- |
| 适用条件 | 说明什么事实、判据缺口或合法入口使该技能值得使用。 |
| 行动选择 | 给出选用工具的依据和必要前置条件。只有真实的数据依赖才写成先后步骤。 |
| 结果与边界 | 指明谁消费结果，什么可以采信，以及失败、缺失或低置信时应保留什么状态。 |
| 示例 | 用一个会改变决定的具体情形说明如何取舍。例中的药材、视野和次序只用于说明。 |

维护时逐项对照 `registry.json`、工具契约和实际动作提议。技能名与用途在注册索引维护，正文只写会影响选择或解读的信息。五张 `SKILL.md` 的内容会计入运行签名，改动后新任务会产生新的签名。[签名范围](../lib/workflow/workflow_backend.py)
